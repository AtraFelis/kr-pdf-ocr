# Git 컨벤션

프로젝트 전체에 적용한다. 문서 간 충돌 시 [AGENTS.md](../../AGENTS.md)를 기준으로 하며, 충돌 통지·원인 분석·오류 검토 절차는 해당 파일을 따른다.

## 브랜치

- 기본 브랜치는 `main`이다. 최초 커밋은 현재 시제품과 문서를 한 번에 기록하는 기준점으로 만든다.
- 이후 구현은 `codex/<작업명>` 브랜치에서 진행한다. 예: `codex/paragraph-restoration`, `codex/page-selection`.
- 브랜치 이름은 소문자 영어와 하이픈을 사용한다. 하나의 브랜치는 하나의 작업 목적을 가진다.
- GitHub 연결 이후에는 작업 브랜치를 PR로 검토하고 `main`에 병합한다. 푸시·PR 생성·병합은 사용자의 해당 작업 지시 범위에서 수행한다.

## 커밋 메시지

형식: `<type>(<scope>): <한국어 설명>`. 범위가 불필요하면 괄호를 생략한다. 제목은 72자 이내로 작성한다.

- `feat`: 사용자 기능 추가
- `fix`: 오류 수정
- `docs`: 문서 변경
- `refactor`: 동작을 유지하는 구조 개선
- `test`: 테스트 추가·수정
- `perf`: 성능 개선
- `build`: 의존성·빌드 설정 변경
- `ci`: 자동 검사 설정 변경
- `chore`: 기타 유지 관리

예: `feat(text): 문단 내부 줄바꿈 복원 추가`, `fix(pdf): 페이지 범위 초과 처리 수정`.

한 커밋에는 하나의 변경 목적을 담는다. 변경 이유나 제한 사항이 제목만으로 불명확하면 본문에 설명한다. 커밋 본문에는 수행한 검증과 수행하지 못한 검증을 기록한다. 단순 문서 변경은 문서 참조·일치 여부 검토를 기록한다.

## 추적 대상과 제외 대상

- 소스 코드, 합성 자료 기반 테스트, 설정, 의존성 잠금 파일과 개발 문서를 추적한다.
- `.venv/`, 캐시, 모델 가중치, 실제 PDF, 실제 문서의 정답 TXT, OCR 결과, 로그와 비밀 정보는 추적하지 않는다.
- `models/`, `samples/input/`, `samples/expected/`, `output/`에는 폴더 유지용 `.gitkeep`만 추적한다.
- 공개할 문서에도 실제 원문이나 개인정보를 복사하지 않는다. 실행 기록에는 필요한 지표와 제한 사항만 적는다.
- 제외 파일을 강제 추가하지 않는다. 테스트 자료가 필요하면 합성하거나 배포 가능한 자료를 별도 테스트 폴더에 둔다.
- `.gitattributes`로 일반 텍스트는 LF, Windows 실행용 `.bat`는 CRLF로 관리한다.

## 작업 및 검증 절차

프로젝트 루트에서 작업한다.

1. `git status --short`와 `git diff`를 확인해 기존 사용자 변경을 구분한다.
2. 관련 기능을 구현하고 필요한 테스트·문서를 같은 변경에서 갱신한다.
3. `AGENTS.md`에 등록된 변경 관련 검사 명령을 실행한다. 코드 변경은 테스트·Ruff 검사·포맷 검사를 통과시킨다. 의존성 변경에는 `python -m pip check`도 수행한다.
4. `git add <파일 또는 폴더>`로 관련 파일만 추가한다. 범위를 확인하지 않은 전체 추가와 `git add -f`는 사용하지 않는다.
5. `git diff --cached --stat`, `git diff --cached`, `git diff --cached --check`로 내용·제외 대상·공백 오류를 점검한다.
6. 커밋 후 `git status --short`와 `git log -1 --oneline`을 확인한다. 사용자 변경이 남아 있으면 보존하고 완료 보고에서 구분한다.

## GitHub 연결과 PR

- 저장소 설명은 [GitHub 설명](../GITHUB_DESCRIPTION.md)을 사용한다. 저장소 이름·소유자·공개 여부는 사용자가 정한 값을 따른다.
- 빈 GitHub 저장소를 생성하면 최초 로컬 기록을 그대로 연결할 수 있다. 이미 커밋이 있는 원격 저장소는 이력을 확인하고 통합 방법을 정한다.
- 실제 원격 URL을 확인한 후 `origin`에 등록한다. URL과 계정을 추측하지 않는다.
- 최초 업로드는 `git push -u origin main`으로 수행한다. 이후에는 작업 브랜치를 푸시하고 PR을 만든다.
- PR에는 문제, 변경 결과, 검증과 남은 제한을 적는다. 기획·명령·구조 변경이 있으면 관련 문서도 함께 갱신한다.
- 인증 정보는 원격 URL·문서·스크립트에 넣지 않는다. 인증 도구의 자격 증명 관리를 사용한다.

## 금지 사항

- 사용자 변경을 덮어쓰는 `reset --hard`, `clean -fd`, 강제 체크아웃을 수행하지 않는다.
- 공유된 이력을 임의로 재작성하거나 강제 푸시하지 않는다.
- 실패한 검사를 숨기거나 실제 수행하지 않은 검사를 통과했다고 기록하지 않는다.
- 로컬 커밋을 원격 백업이나 GitHub 업로드 완료로 표현하지 않는다.
