## 다음 개발 우선순위

기준일: 2026-10-13. [PR #8](https://github.com/AtraFelis/kr-pdf-ocr/pull/8)은 병합됐으며 `main`에 아래 구현이 포함된다.

- 고유명사 사용자 사전·모델 정보·VL 1.6 구조화 Markdown과 이미지 저장.
- `sample_ocr_err.pdf` 2페이지에서 작은 닫는 따옴표 때문에 문단 복원·Kiwi가 중단되던 문제 수정. 샘플 1~2페이지의 적용과 원시 결과 보존 확인.
- 한글 인용문의 여는 따옴표 앞 공백 보완.
- PP-OCRv5 재인식 후보 비교, 선택 줄의 VL 1.6·Qwen 재인식, 후보의 편집기 반영·실행 취소.

PR #8의 마지막 코드 변경 기록은 전체 152개 검사 통과이며 [검증 범위와 제한](history/VISUAL_RETRY_ERRORS.md)을 따른다. 이는 과거 실행 결과로, 문서 최신화에서 재실행한 결과가 아니다. 아래는 다음 순서다. `gec_kr`은 로컬 CPU/GPU 합성 20개 비교를 완료했으며 과잉 교정·핵심 오자 미해결과 라이선스 미확인으로 제품 도입을 보류했다. [평가 기록](history/GEC_EVALUATION.md)을 따른다.

1. **교정 실행 조건·자료 확인:** KoGEC 두 모델의 공개 파일과 제한된 GPU 진단을 확인했으나 교정 토큰 매핑 누락으로 정식 평가·도입은 보류했다. [확인 기록](history/KOGEC_CHECKPOINT.md)을 따른다. 공식 토크나이저·추론 설정을 확보하면 재평가하며 다른 실행 가능한 후보와 실제 오자 자료도 확대한다. `gec_kr`의 공식 생성 조건 첫 평가는 완료했으며 핵심 오자·문장부호 미해결과 정상 문장 변경을 기록했다.
2. 평가 결과가 유효하면 TXT 원문·교정 후보·변경 위치 비교와 사용자 채택 기능 연결. 원시 결과·편집본을 보존하며 자동 교체하지 않는다. 채택 여부는 평가 후 결정한다.
3. 후속 품질 개선: 미해결 겹침·좌표 누락의 보정 제외 이유 표시와 정상 영역 부분 복원, 짧은 대사·문장부호의 해상도·여백·정확도 비교, 제목·목록·각주·단어·페이지 간 문단 연결, Markdown 표·수식·읽기 순서 확대.
4. CPU/GPU 성능·메모리·오프라인 처리·Windows 배포 검증.

작은 닫는 부호로 인한 샘플의 보정 중단은 완료 항목이다. 모든 좌표 오류의 부분 복원과 모든 문장부호의 정확도 개선까지 완료한 것으로 확대 해석하지 않는다.

사용자 사전은 합성 사례의 품질·입력·저장·화면 흐름을 확인했다. 실제 문서별 품질 확대와 VLM 사전 활용은 추가 평가한다.

텍스트 중심 문서는 PP-OCRv5 + TXT, 복잡한 문서는 VL 1.6 + Markdown을 추천하는 별도 흐름으로 진행한다. Markdown은 샘플 실행·저장·취소를 확인했으며 [설계 문서](MODEL_AND_EXPORT.md)를 따른다.
