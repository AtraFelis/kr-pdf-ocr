# 데스크톱 프로그램 사용법

## 실행

프로젝트 폴더의 `start.bat`를 더블 클릭한다. 터미널에서는 프로젝트 가상환경으로 다음 명령을 사용한다.

```powershell
.\.venv\Scripts\python.exe -m pdf_ocr.gui
# PDF를 바로 열기
.\.venv\Scripts\python.exe -m pdf_ocr.gui samples/input/sample.pdf
```

현재는 프로젝트 환경에서 실행하는 시제품이다. 별도 설치 프로그램·EXE 배포는 후속 작업이다. GUI는 PySide6-Essentials 6.10.2와 shiboken6 6.10.2를 사용한다. 환경을 새로 구성할 때는 AGENTS.md의 설치 명령과 의존성 잠금 파일을 따른다.

앱 내부는 Windows의 다크 모드 설정과 관계없이 밝은 테마를 사용한다. 배경·글자·입력창·버튼·미리보기 여백을 같은 색상 체계로 표시한다. 색상 수정 후에는 실행 중인 앱을 닫고 `start.bat`로 다시 실행한다. 창 제목 표시줄과 Windows 파일 선택 창은 운영체제 설정에 따라 표시될 수 있다.

## 작업 흐름

1. **PDF 열기** 또는 드래그 앤 드롭으로 파일을 연다.
2. 왼쪽 목록에서 처리할 페이지를 체크한다. 범위·제외 입력은 **페이지 범위 적용**을 누르거나 OCR 실행 시 적용한다. 페이지 번호는 PDF 순서다.
3. 페이지를 클릭해 미리보기를 연다. 확대 비율을 바꾸거나 마우스로 사각형을 그린다. 선택은 현재 페이지에 즉시 저장된다.
4. 숫자 좌표를 바꾸거나 다른 페이지에도 적용하려면 적용 범위에서 **현재 페이지 / 체크한 페이지 / 모든 페이지**를 고르고 **영역 적용**을 누른다. **전체 영역**도 같은 범위에 적용된다.
5. 인식 모델과 **처리 장치(CPU / GPU)**를 선택하고 **OCR 실행**을 누른다. 완료되면 오른쪽에서 결과를 확인·수정한 뒤 **TXT 저장**을 누른다.

## CPU와 GPU 선택

모델 정보 아이콘과 TXT/Markdown 출력 형식 선택은 개발 예정이다. 현재 화면은 TXT 저장을 제공하며, 복잡한 문서의 구조 분석·Markdown 출력은 [추가 설계](MODEL_AND_EXPORT.md)를 참조한다. 모델 설명은 아이콘을 눌렀을 때만 열고 기존 CPU 자원 안내는 계속 표시하는 방향이다.

모델 아래에서 처리 장치를 선택한다. 시작 시에는 GPU 없는 환경에서도 실행할 수 있는 CPU를 선택한다. 모델을 바꿔도 사용자가 고른 처리 장치는 유지되며 OCR 실행 중에는 바꿀 수 없다.

- **CPU:** GPU보다 오래 걸릴 수 있고 CPU 사용량이 늘어 다른 작업이 느려질 수 있다는 안내를 계속 표시한다. CPU 선택 자체가 인식 정확도를 낮추는 것은 아니다. VL·Qwen 모델은 CPU에서 특히 느리고 메모리도 많이 사용한다.
- **GPU:** NVIDIA GPU와 선택한 모델에 맞는 실행 환경이 필요하다. GPU를 명시적으로 선택했는데 사용할 수 없으면 실패 원인을 안내한다. 자동으로 CPU로 전환하지 않는다. 드라이버·환경을 확인하거나 CPU를 선택한다.

이 PC의 PP-OCRv5는 `.venv-paddle`의 PaddlePaddle-GPU 3.2.2 / CUDA 12.9 환경에서 CPU와 GPU를 모두 실행한다. VL·Qwen은 `.venv`의 기존 PyTorch GPU 환경을 사용한다. Windows CUDA 라이브러리 충돌을 피하도록 실행 프로세스와 환경을 분리한다. 전용 환경이 없으면 PP-OCRv5도 현재 Python 환경에서 실행하므로 GPU용 환경을 별도로 준비해야 한다. 설치 방법은 AGENTS.md를 참조한다.

명령행에서는 `--device cpu`, `--device gpu`, `--device auto`를 사용한다. 생략하면 PP-OCRv5는 CPU, VL·Qwen은 GPU 우선이다. `auto`만 GPU를 사용할 수 없을 때 CPU로 전환한다. PP-OCRv5 GPU 명령은 `.venv-paddle`의 Python으로 실행한다. `summary.json`에는 요청한 장치와 실제 장치를 기록한다. 명령행의 실험적 `--vl-lines`는 기존 CPU 검출기와 선택한 VLM 장치를 함께 사용한다.

CPU·GPU 처리 시간과 샘플 비교 조건은 [장치 선택 검증 기록](history/IMPLEMENTATION_LOG.md#cpu와-gpu-선택)을 참조한다. 장치 변경 후에도 원문과 결과를 대조한다.

## 선택과 결과 보존

고유명사 사용자 사전 선택·관리와 사전 적용 재보정은 다음 개발 기능이다. 현재 화면에는 사전 기능이 없으며 계획은 [사용자 사전 설계](USER_DICTIONARY.md)를 참조한다.

- 미리보기는 96 DPI, OCR은 300 DPI다. 숫자 입력은 화면에 표시된 미리보기 이미지 크기의 픽셀 기준이며, 확대해도 기준 크기는 변하지 않는다.
- 영역은 상대 좌표로 저장한다. 다른 크기 페이지에 같은 영역을 적용하면 같은 비율이 적용된다. 경계에 걸친 글자는 잘릴 수 있으므로 미리보기를 확인한다.
- 기본 인식 모델은 PP-OCRv5 한국어다. PP-OCRv5·VL 1.6·Qwen 모두 처리 장치를 별도로 선택한다. 최종 모델 확정은 별도 평가 후 결정한다.
- 기본 모델에서는 로컬 한국어 띄어쓰기 보정 제안이 기본 체크되어 있다. 자체 문단을 출력하는 VLM을 선택하면 해당 보정 옵션은 비활성화한다. 병기 한자는 기본 제외한다.
- 오른쪽 편집기는 완료된 선택 페이지의 통합 결과다. 미리보기 페이지를 바꿔도 편집 내용은 유지된다. 페이지별 텍스트 편집·저장 UI는 아직 제공하지 않는다.
- 수정한 결과를 저장하지 않고 PDF를 바꾸거나 OCR을 다시 실행하거나 창을 닫으면 확인한다. 기존 TXT 덮어쓰기도 확인하고 원본 PDF로 저장하는 것은 거부한다.

## 진행·취소·오류

OCR은 별도 작업 프로세스에서 실행해 화면의 응답을 유지한다. 진행률은 실제 완료 페이지 수를 표시한다. 취소하면 현재 처리 중인 페이지가 끝나지 않을 수 있지만 이미 저장된 결과는 남고 편집기에 표시된다. 실패·취소는 완료로 표시하지 않는다.

작업 파일은 `output/gui-작업ID/`에 보관한다. `regions.json`은 설정, `process.log`는 실행 기록, `result/`는 원시 OCR·이미지·통합 TXT다. 문서와 결과는 외부 서버로 전송하지 않으며 Git 추적 대상에서도 제외된다.

화면에는 검토 항목 수를 표시한다. 단어 연결·띄어쓰기 제안·좌표 없는 결과 등 세부 항목은 페이지 JSON에 남는다. 글자별 신뢰도 강조나 원문 위치별 검토 화면은 후속 작업이다.

## 검증 범위

수행한 UI·샘플 실행·색상 수정·장치 선택 확인은 [데스크톱 검증 기록](history/IMPLEMENTATION_LOG.md#데스크톱-화면)에 보관한다. 모든 창 크기·고해상도 화면·긴 문서 장시간 사용, 실제 Windows 다크 모드 재실행, VLM 전체 페이지 CPU 처리와 모든 장치별 취소·실패 조건은 추가 확인이 필요하다.
