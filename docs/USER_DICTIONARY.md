# 고유명사 사용자 사전 설계

상태: **개발 예정·미구현**. 요구사항은 [기획서](PLAN.md#38-고유명사-사용자-사전-추가-기획미구현), 작업 순서는 [개발 목록](TASKS.md#다음-개발-우선순위), 도입 근거는 [설계 결정 기록](history/USER_DICTIONARY_DECISION.md)을 참조한다.

## 목적과 첫 적용 범위

인명·지명·회사명·작품 용어처럼 기본 사전에 없는 단어가 보정 과정에서 잘못 나뉘는 문제를 줄인다. 사용자 사전은 선택 기능이며 등록된 표기를 우선 고려하도록 한다. 모든 문서에서 개선된다고 단정하지 않는다.

첫 구현은 PP-OCRv5 결과의 Kiwi 띄어쓰기 보정과 좌표가 있는 저장 OCR 결과의 재보정에 적용한다. 현재 VL·Qwen 결과에는 Kiwi 보정을 적용하지 않으므로 사전을 자동 적용하지 않는다. VLM의 표기 보호나 OCR 단계에서의 사전 활용은 이후 별도 비교한다.

## 사전 만들기와 관리

- 사전 이름을 정하고 단어를 추가·수정·삭제한다. 작품·분야별 사전을 만들고 한 작업에 하나를 선택하거나 사용하지 않을 수 있다.
- 인명뿐 아니라 공백이 있는 복합 이름도 등록한다. 조사까지 붙은 문장보다 기본 이름을 등록한다.
- UTF-8 TXT를 한 줄에 한 단어 형식으로 가져오고 같은 형식으로 내보낸다. UTF-8 BOM도 허용한다.
- 빈 줄은 무시하고 중복 항목을 확인한다. 단어 앞뒤 공백과 연속 공백을 정리하되 단어 내부에 필요한 공백·대소문자·글자는 보존한다.
- 공백을 제외하면 같은 글자인데 등록 표기가 다른 항목은 충돌로 표시하고 사용자가 표기를 선택하도록 한다. 조용히 덮어쓰지 않는다.
- 잘못된 파일·빈 사전·변환할 수 없는 인코딩은 사용자에게 원인과 조치를 안내한다. 실패한 가져오기로 기존 사전을 지우지 않는다.

## 저장 형식과 개인 데이터

앱 내부 저장은 버전·사전 이름·단어 목록을 포함한 UTF-8 JSON으로 계획한다. 다음은 실제 문서에서 가져오지 않은 예시다.

```json
{
  "version": 1,
  "name": "예시 작품",
  "words": ["하루카", "푸른별 연구소"]
}
```

사용자 사전 기본 저장 위치는 `user_data/dictionaries/`로 계획한다. 구현하는 변경에서 해당 위치의 Git 제외 설정도 추가한다. 현재는 폴더·설정·파일 처리 코드가 없는 기획 상태다. 사용자 사전은 개인 데이터로 취급하고 외부 전송·Git 추적을 하지 않는다. 기존 파일 덮어쓰기·삭제와 저장하지 않은 사전 편집 내용 처리는 확인을 받는다.

## 처리 순서와 결과 보존

1. 사용자가 사전을 선택한다. 보정 전에 파일과 충돌 항목을 확인한다.
2. PDF의 선택 페이지·영역을 OCR하고 원시 글자와 위치를 보존한다.
3. 기존 방식으로 문단을 복원한다.
4. Kiwi에 선택 사전의 단어를 고유명사로 등록한 뒤 해당 문단의 띄어쓰기를 보정한다.
5. 공백을 제외한 글자가 보정 전후에 같은지 검사하고 변경 제안을 기록한다.
6. 결과를 원문·사전 미적용 결과와 비교한 뒤 UTF-8 TXT로 저장한다.

사전 적용은 이름이 잘못 분리되는 오류를 줄이는 데 사용한다. OCR이 다른 글자로 읽은 이름을 유사한 사전 단어로 자동 치환하지 않는다. 일반 단어와 겹치거나 판단이 모호하면 확인 대상으로 남긴다. 원래 문단 경계를 사전 때문에 연결하지 않는다.

사전 등록 방식·가중치와 공백 포함 이름의 실제 동작은 같은 오류 사례로 확인한 뒤 결정한다. 단어 등록만으로 표기가 반드시 보호된다고 가정하지 않는다. 사용자 화면에 내부 품사 코드·가중치를 입력하게 하지 않는다.

## 재보정과 화면 연결

저장 OCR JSON에서 재보정하는 경로를 먼저 연결한다. OCR 모델을 다시 실행하지 않고 사전 적용/미적용 결과를 새 출력 경로에 생성한다. 기존 결과와 사용자 편집 내용을 덮어쓰지 않는다. 화면 재보정은 화면에서 직접 편집한 텍스트를 덮어쓰지 않도록 별도 비교 결과로 제공한다.

화면에는 사전 선택·관리·TXT 가져오기/내보내기와 적용 여부를 제공한다. PP-OCRv5의 띄어쓰기 보정과 함께 사용할 수 있는지 표시하고, 아직 지원하지 않는 모델에서는 이유를 안내한다. 실행 중에는 현재 작업의 사전 내용을 고정한다.

결과에는 적용 사전의 이름·버전·내용 식별값과 보정 전후 제안을 기록해 어떤 사전을 썼는지 확인할 수 있게 한다. 작업 뒤 사전이 바뀌어도 과거 실행 조건을 구분할 수 있어야 한다. 사전 파일 자체와 기록은 로컬 추적 제외 경로에 보관한다.

## 구현 순서와 완료 기준

1. 사전 파일 읽기·입력 검사·저장과 합성 고유명사 오류 사례를 준비한다.
2. Kiwi 사용자 단어 등록, 보정 옵션과 저장 OCR 재보정에 연결한다.
3. 화면의 사전 편집·선택과 파일 가져오기/내보내기를 연결한다.
4. 적용 전후 비교·작업 사전 식별 정보·편집 결과 보호를 연결한다.

완료 판단에는 단일 이름, 공백 포함 이름, 이름+조사, 줄 경계에서 나뉜 이름, 일반 단어와 겹치는 이름, 중복·충돌 항목, 사전 미선택, 잘못된 파일과 UTF-8 저장을 포함한다. 문단 경계·공백 외 글자·원본·기존 출력·사용자 편집 내용을 보존하는지 확인한다.

사전 적용 전후의 고유명사 표기 오류와 일반 문장 띄어쓰기 오류를 같은 정답으로 비교한다. 개선·변화 없음·악화를 구분하고 OCR 문자 오류와 보정 오류를 분리한다. 결과는 `docs/history/`에 조건과 함께 기록하며, 확인한 기능만 개발 목록에서 완료 처리한다.

현재는 사전용 실행 명령·화면을 제공하지 않는다. 구현하는 변경에서 설치·실행·검증 명령과 실제 지원 범위를 관련 문서에 등록한다.
