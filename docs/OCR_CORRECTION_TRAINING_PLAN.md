# 한국어 OCR 문자 교정 모델 학습 기획서

작성일: 2026-10-13. 상태: 기획. 이번 문서 작성에서 학습 환경 설치·데이터 수집·파인튜닝을 실행하지 않았다.

## 1. 목적과 성공 방향

한국어 PDF의 OCR 결과에서 잘못 인식한 부분만 최소한으로 수정하는 로컬 모델을 학습한다. 정답은 자연스러운 문장이 아니라 **원본 이미지에 실제로 적힌 문장**이다. 오류가 없는 문장은 그대로 출력하고 고유명사·숫자·영어·대사 말투를 보존한다.

예시: `그는 훌륨한 연주를 들려주었다. → 그는 훌륭한 연주를 들려주었다.`는 원하는 교정이다. `훌륨한 → 대단한`처럼 다른 단어로 바꾸거나 문장을 다시 쓰는 것은 의역으로 분류한다. 파인튜닝으로 의역이 완전히 없어질 것이라고 가정하지 않는다.

이 기획서는 **별도 세션의 모델 학습·평가 작업**을 위한 것이다. 기존 프로젝트의 공통 규칙은 [AGENTS.md](../AGENTS.md), 제품 요구사항은 [기획서](PLAN.md)를 따른다. 별도 저장소로 옮길 때도 로컬 처리·원문 보존·Docstring·데이터 제외 원칙을 해당 프로젝트에 명시한다.

## 2. 배경과 현재 확인 범위

- Kiwi는 공백을 보정하며 프로젝트 정책상 공백 외 글자를 변경하지 않는다. 문자 치환 오류의 해결은 별도 기능이다.
- `gec_kr`은 합성 자료에서 일부 오류를 개선했지만 핵심 오자 미해결과 정상 문장 변경을 확인해 앱 도입을 보류했다.
- 기본 KoBART를 교정 학습 없이 직접 생성한 로컬 테스트에서는 빈 출력·반복 생성이 있었다. 이것은 OCR 교정용으로 파인튜닝한 모델의 성능을 평가한 결과가 아니다.
- KoGEC 공개 가중치는 교정용 토큰 매핑을 확인하지 못해 논문 방식의 정식 평가·도입을 보류했다. 한국어→한국어 제어 조건의 진단 결과를 모델의 정확도나 학습 정답으로 사용하지 않는다.
- 후보 평가 도구·기록은 [PR #10](https://github.com/AtraFelis/kr-pdf-ocr/pull/10)에 있다. 해당 PR의 병합 여부와 새 세션의 체크아웃 상태를 확인한다. 이 학습 기획은 PR #10의 코드 설치를 필수 전제로 삼지 않는다.

## 4. 입력·정답 정책

첫 학습 단위는 한 문장 또는 짧은 본문 조각이다. 문단/페이지 연결 문제와 문자 교정 문제를 구분한다. 문장 분리 자체가 틀렸거나 입력이 잘린 사례는 별도 표시한다.

입력 위치를 실험별로 고정한다.

1. **A 경로:** 문단 복원 후, Kiwi 적용 전 텍스트 → 원본에 맞는 정답.
2. **B 경로:** 같은 사례를 Kiwi 처리한 텍스트 → 동일한 정답.

A부터 시작하고 B는 비교 실험으로 둔다. 학습 시 A를 사용했다면 평가·추론에도 A를 사용한다. 서로 다른 전처리 결과를 표시 없이 섞지 않는다. 원시 OCR·문단 복원·Kiwi 결과는 별도 필드로 보존한다.

- 원본이 문법적으로 어색해도 임의로 윤문하지 않는다.
- OCR 신뢰도나 다른 모델의 후보를 정답으로 간주하지 않는다. 이미지 대조가 필요하다.
- 고유명사는 원본 표기를 기준으로 한다. 등록 이름이 이미 정확한 사례와 이름 자체가 잘못 인식된 사례를 구분한다.
- 누락 문장부호는 이미지에서 확인할 수 있는 경우에만 정답에 넣는다.
- `ac → 응?`처럼 텍스트만으로 결정하기 어려운 사례는 평가의 어려운 사례로 유지하고 원본 영역 재인식 대상으로 표시한다. 이런 사례의 성공을 보편적인 복원 능력으로 확대하지 않는다.
- 학습 입력·정답을 조용히 잘라 맞추지 않는다. 토큰 상한 초과 사례는 제외/분할 여부와 이유를 기록한다.
- Unicode·따옴표·줄바꿈 정규화 정책을 고정하고 원본 필드를 보존한다. 정규화로 달라진 위치를 원시 좌표라고 표시하지 않는다.

## 5. 데이터 형식과 검수

로컬 UTF-8 JSONL을 기본 형식으로 한다. 아래는 직접 작성한 합성 예시다.

```json
{"id":"synthetic-001","document_group":"synthetic-family-001","source":"그는 훌륨한 연주를 들려주었다.","target":"그는 훌륭한 연주를 들려주었다.","input_stage":"paragraph_before_kiwi","error_types":["character_substitution"],"origin":"synthetic","review_status":"verified","protected_spans":[],"reference_basis":"directly_authored","split":"unassigned"}
```

필수 항목은 `id`, `document_group`, `source`, `target`, `input_stage`, `error_types`, `origin`, `review_status`, `reference_basis`다. 실제 문서에는 로컬 원본 식별값·페이지·영역·OCR 엔진/버전·설정·검수 이력을 덧붙인다. 원본 경로·본문·해시는 외부 로그나 GitHub 본문에 공개하지 않는다.

`review_status`는 미검수/검증 완료/보류를 구분한다. 이미지가 불명확하거나 정답 의견이 갈리는 사례는 보류하고 첫 학습에 넣지 않는다. 첫 단계는 수집용 CLI·JSONL 편집/검사로 충분하며 별도 GUI는 필수 기능이 아니다.

보호 구간은 source 기준 Unicode 코드 포인트의 `[start, end)`와 문자열을 함께 저장하고 일치 여부를 검사한다. 이미 정확하다고 확인한 고유명사·숫자 등을 표시한다. source와 target이 다른 구간을 무조건 보호하거나 잘못 인식된 이름을 보호 표기로 고정하지 않는다.

## 6. 자료 구성과 누수 방지

첫 소규모 실험의 **잠정 목표**는 검수된 500~2,000쌍이다. 이 숫자는 실험 시작 규모이며 정확도를 보장하는 최소 수량이 아니다. 자료가 부족하면 확보한 수량과 유형별 편향을 보고한다.

- 정상→정상 보존 사례를 약 40~60%로 시작해 복사와 교정의 균형을 검증한다. 최적 비율은 검증 자료로 결정한다.
- 오류 사례는 실제 OCR 결과를 우선한다. 글자 치환/누락/삽입, 공백, 문장부호를 구분한다.
- 고유명사·숫자·영어·대사 말투와 제목처럼 수정하면 안 되는 표현을 포함한다.
- 합성 오류는 실제 OCR에서 관찰한 혼동·분리·누락을 반영하고 생성 조건을 기록한다. 무작위 오타만으로 실제 오류를 대체하지 않는다.
- 실제 문서의 학습·보관·배포 가능 범위를 확인한다. 사용자 보유 자료가 모델·데이터 공개에도 사용 가능한 것으로 자동 간주하지 않는다.

학습/검증/최종 평가 비율은 잠정 70/15/15다. 비율보다 **문서 단위 분리**를 우선한다. 같은 책·연속 페이지·같은 문장의 Kiwi 변형·같은 합성 문장 가족은 하나의 그룹으로 묶어 한쪽 split에만 넣는다. 학습 자료에서 만든 증강문을 최종 평가에 넣지 않는다.

정확 중복·유사 문장을 검사하고 문서별 분리 목록·시드·데이터 버전·내용 식별값을 저장한다. 현재 반복해서 확인한 소규모 예제들은 개발용 회귀 자료로 취급하고 최종 성능을 주장할 독립 자료와 구분한다. 최종 평가 세트는 모델·설정 선택에 사용하지 않는다.

## 7. 기반 모델과 학습 방식

첫 후보는 [SKT 공식 기본 KoBART](https://github.com/SKT-AI/KoBART)다. 교정용 추가 학습을 위한 기반 모델로 사용한다. 공식 README가 연결하는 `skt/kobart-base-v1`을 출발 후보로 삼되 다운로드 전에 실제 리비전·파일·토큰·라이선스 고지를 고정한다. 다른 배포본으로 바꾸면 별도 실험으로 기록한다.

공식 저장소의 [Modified MIT 고지](https://github.com/SKT-AI/KoBART/blob/main/LICENSE)를 확인하고 선택한 가중치·토크나이저·학습 자료의 사용 조건도 기록한다. `gec_kr`의 미확인 사용 조건이나 KoGEC의 토큰·비상업 조건을 그대로 계승하는 모델을 기본 후보로 삼지 않는다.

첫 실험은 Seq2Seq **LoRA**를 우선한다. 기반 가중치를 고정하고 일부 가중치만 학습하는 방식으로 메모리 부담을 줄인다. LoRA 자체가 최소 교정이나 원문 보존을 보장하지 않으며 자료·평가·반영 정책을 함께 설계한다. [PEFT 설명](https://huggingface.co/docs/peft/en/conceptual_guides/lora)

초기 설정은 아래 제안에서 작은 실행으로 확인한다. 모두 미검증 시작값이며 최적값이 아니다.

- 토큰 길이: 입력·정답 각각 128부터 시작. 상한 초과 처리와 원문 보존을 검사한다.
- LoRA rank 8, alpha 16, dropout 0.05. 실제 모듈 이름을 조사한 뒤 encoder/decoder attention의 적용 범위를 기록한다.
- 학습률 `1e-4`를 첫 후보로 두고 필요하면 `5e-5`와 비교한다.
- micro batch 1~2, gradient accumulation으로 유효 batch 8~16을 목표로 메모리를 실측한다.
- 최대 3 epoch의 짧은 실험과 검증 기반 조기 중단을 사용한다. epoch를 늘리기 전에 정상 문장 훼손과 과적합을 확인한다.
- GPU·라이브러리가 지원하고 수치 안정성을 확인한 정밀도를 사용한다. RTX 5070에서 반드시 특정 설정이 들어간다고 단정하지 않는다.
- 시작 디코딩은 샘플링 없는 greedy로 고정하고 빔 탐색 비교는 검증 세트에서만 수행한다.

토크나이저와 기반 가중치의 어휘 크기·BOS/EOS/PAD·decoder start·입출력 경계·출력 투영의 사전 학습 가중치 연결을 확인한다. 누락 가중치나 임의로 추가한 토큰이 있는 상태를 정상 학습으로 처리하지 않는다. 학습 전 작은 배치의 forward/backward와 유한한 loss·체크포인트 저장/재로딩을 확인한다.

처음에는 표준 supervised Seq2Seq loss와 보존 사례로 시작한다. 효과가 부족하면 정상 구간 변경을 더 억제하는 목적 함수·복사 제약·편집 예측을 별도 실험으로 검토한다. 문장 전체 생성 대신 편집을 예측하는 [GECToR 연구](https://arxiv.org/abs/2005.12592)는 후속 방향이며 한국어 OCR 지원이나 구현 완료를 뜻하지 않는다.

## 8. 환경·저장·재현성

다른 세션과 같은 Git 체크아웃을 동시에 수정하지 않도록 독립 작업 폴더/워크트리 또는 별도 학습 저장소를 사용한다. 실제 경로는 새 세션 시작 시 확인한다. 이번 기획서 작성은 폴더·저장소·새 세션을 생성한 작업이 아니다.

- 학습용 전용 가상환경과 의존성 잠금 파일을 만든다. 기존 `.venv`, `.venv-paddle`, `.venv-doc-parser`는 변경하지 않는다.
- Python·PyTorch·Transformers·PEFT·CUDA·드라이버·GPU/VRAM·메모리·정밀도·시드를 기록한다. 필요한 패키지·버전은 새 환경에서 실제 실행한 뒤 잠근다.
- 모델 다운로드만 네트워크를 사용한다. 학습·평가·로그 기록은 로컬에서 수행하고 외부 실험 추적과 자동 업로드를 끈다.
- 공개 저장소에는 코드·설정·합성 예제·재현 절차·비식별 지표만 추가한다. 실제 문서·정답·가중치·예측 본문·경로가 든 로그는 제외한다.
- 로컬 데이터, 모델, 실험 출력과 가상환경의 Git 제외를 **자료를 복사하기 전에** 확인한다. 전용 환경의 제외 규칙은 환경 도입 변경에서 추가한다.
- 매 실행은 새 디렉터리와 run ID를 사용한다. 기존 체크포인트를 덮어쓰지 않으며 중단 후 재개는 명시적으로 선택한 체크포인트만 사용한다.

산출물 구조는 계획 단계이며 새 세션에서 결정한다. 코드와 실험 설정, 로컬 데이터, 모델/어댑터, 실행 결과를 분리하고 기존 앱 소스와 사용자 편집본을 수정하지 않는다.

## 9. 평가·채택 기준

같은 독립 평가 자료에서 원문 유지, Kiwi, 미학습 기반 모델, 학습 모델을 비교한다. 학습 때 선택한 A/B 입력 경로를 맞추고 경로가 다르면 결과를 나눠 보고한다. 사용할 수 있는 기존 교정 모델은 고정 설정의 참고 비교로만 포함한다.

### 필수 지표

- 전체 및 오류 유형별 CER·편집 거리·정답 일치율. 공백 포함/제거를 구분하고 같은 분모로 비교한다.
- 오류 문장에서 실제 오류를 고친 비율과 새 오류를 만든 비율. 정상 문장이 많아 복사만 잘해도 좋은 점수가 나오지 않도록 별도로 보고한다.
- 정상 문장 변경률, 정상 문장의 공백 외 글자 변경률.
- 고유명사·숫자·영어 보호 구간 훼손률과 틀린 이름을 실제로 복구했는지.
- 의역·근거 없는 내용 추가/삭제의 사람이 확인한 사례 수.
- 빈 출력·잘림·반복·실행 실패율. 실패 시 원문 유지 결과와 성공 후보만의 결과를 구분한다.
- CPU/GPU 시간·초기화·프로세스 메모리·VRAM 및 토큰 길이별 조건. 반복 측정·워밍업을 구분한다.

초기 채택 방향은 오류 유형별 실질적인 개선과 보존성 유지다. 개발용 작은 보존 사례에서 새로운 의역·정상 글자·숫자 손상이 하나라도 나오면 그 모델의 앱 연결을 보류하고 원인을 분석한다. 소규모 검사에서 0건이라는 사실을 일반 오류율 0%로 표현하지 않는다. 최종 허용 수치·평가 자료 규모는 기준 성능을 얻은 후 학습 설정 비교 전에 확정한다.

유효한 모델도 먼저 사용자 확인용 후보로만 검토한다. 변경량 상한·보호 구간 검사·불확실한 교정 거부는 위험을 줄이는 장치이며 의미 보존을 보장하는 판정기가 아니다. 일반적인 고유명사 목록이나 편집 횟수만으로 의역을 완전히 검출할 수 있다고 가정하지 않는다.

## 10. 단계별 진행과 완료 조건

1. **작업 범위·환경 조사:** 독립 폴더와 적용 규칙, GPU·모델·토크나이저·사용 조건·저장소 제외를 확인한다. 설치·학습 명령은 아직 미설정이며 실제 확인한 명령만 등록한다.
2. **수집·검수 도구:** 로컬 OCR/정답 쌍을 만들고 이미지 출처·검수·보호 구간·오류 유형을 기록한다. 합성 예제와 입력 오류 검사부터 구현한다.
3. **자료 확정·기준 평가:** 검수된 자료, 문서별 split, 누수 검사와 원문/Kiwi 기준 지표를 확보한다. 부족한 유형과 최종 평가 자료를 보고한다.
4. **소규모 학습:** LoRA 적용·수치 안정성·저장/재개/재로딩을 확인한 뒤 짧게 학습한다. 유효한 자료 없이 긴 학습을 시작하지 않는다.
5. **검증·오류 분석:** 설정별 개선·정상 문장 훼손·의역을 대조해 모델과 디코딩을 선택한다. loss 감소만으로 성공 판정을 하지 않는다.
6. **독립 최종 평가·산출물:** 잠근 평가 세트, 로컬 추론·오프라인 조건·CPU/GPU 측정, 모델 카드·설정·어댑터·재현 명령과 채택/보류 보고서를 완성한다.

각 단계의 코드·문서·필요한 검증은 해당 변경에서 함께 관리한다. 실제 확인한 결과만 완료로 표시하고 미실행 검사는 이유를 적는다. 학습이 실패하거나 효과가 없더라도 데이터·설정·실패 근거를 보존하며 다음 개선 방향을 보고한다. 앱 연결·공개 배포는 이 세션의 완료 조건에 포함하지 않는다.
