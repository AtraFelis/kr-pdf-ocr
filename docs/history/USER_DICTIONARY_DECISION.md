# 고유명사 사용자 사전 도입 결정

기록일: 2026-10-12. 이 문서는 설계 결정 기록이며 기능 구현·정확도 개선 시험의 완료 기록이 아니다. 요구사항은 [기획서](../PLAN.md), 상세 범위는 [사용자 사전 설계](../USER_DICTIONARY.md), 작업 순서는 [개발 목록](../TASKS.md)을 따른다.

## 계기와 확인한 사실

사용자가 고유명사가 들어간 문장에서 띄어쓰기 오류가 집중된다고 보고했고, OCR 또는 Kiwi 보정 전에 고유명사 사전을 준비하는 방안을 제안했다. 구체적인 재현 문장과 오류 유형별 빈도는 아직 정리하지 않았다.

현재 `src/pdf_ocr/spacing.py`는 Kiwi 기본 사전으로 보정하며 사용자 단어를 등록하지 않는다. 공백 외 글자가 달라지면 적용을 중단하고, 좌표 없는 VLM 결과에는 보정을 적용하지 않는다.

설치된 Kiwi 0.24.0의 API에서 `add_user_word`와 기본 고유명사 태그 `NNP`를 확인했다. 공식 문서에는 사용자 단어 등록과 공백을 포함한 단어 지원이 설명되어 있다. [Kiwi 공식 설명](https://github.com/bab2min/kiwipiepy), [사용자 단어 API 문서](https://bab2min.github.io/kiwipiepy/v0.23.1/kr/).

## 결정과 기대 효과

사용자가 선택한 로컬 사전을 Kiwi 보정에 연결하는 방식을 첫 구현으로 삼는다. 기본 사전에 없는 이름을 고유명사로 다루도록 도와 잘못된 단어 분리를 줄일 가능성이 있다. 이는 기대 효과이며 현재 PDF에서 실제 개선된다고 검증한 것은 아니다.

처음부터 사전 전체를 작성하도록 요구하지 않는다. 오류가 생긴 단어를 추가하고 저장 OCR 결과를 다시 보정해 비교할 수 있게 한다. 생성형 OCR 모델을 매번 실행하지 않아도 보정 단계의 영향을 구분할 수 있다.

## 첫 단계에서 확정하지 않은 사항

- 등록 단어의 가중치·표기 보호 방식은 실제 사례 비교 뒤 결정한다. 일반 단어·겹치는 이름에 과도하게 적용되는지도 확인한다.
- OCR에서 글자 자체가 오인식된 이름의 자동 치환은 포함하지 않는다.
- VL·Qwen의 사전 활용, OCR 인식 단계의 사전 활용은 별도 품질 비교 대상으로 둔다.

사용자 사전은 개인 데이터로 로컬에 보관하고 Git에서 제외한다. 상세 형식·저장 위치·화면·검증 기준은 설계 문서에서 관리한다. 이후 구현·시험 결과는 조건과 한계를 포함해 별도로 기록한다.
