# DPI·검출 표시·임의 영역 재인식 구현 기록

기준일: 2026-10-13. PR #12의 검출 누락·사용자 설정 변경에 연결된 완성된 작업 단위로 누적한다. 실제 문서·이미지·후보 출력은 Git에 포함하지 않는다. 현재 동작은 [사용법](../OCR_REVIEW.md)을 따른다.

## 구현과 문서 정리

- 주 화면의 200/300/400/600 DPI 선택을 실제 OCR 프로세스 인자에 전달하고 검출 기준과 함께 기본값 복원을 제공한다.
- 저장된 원시 줄의 전체 페이지 다각형을 상대 좌표로 환산해 녹색으로 표시한다. 확대·DPI·자르기 좌표를 구분하고 없는 좌표를 생성하지 않는다. 잘못된 상대 좌표는 거부한다.
- 재인식 드래그 모드는 기존 추출 영역을 보존한다. 현재 PDF의 명시적인 별도 영역을 PP-OCRv5·VL 1.6·Qwen으로 읽는 TXT 후보 비교 창을 추가한다.
- 매 후보는 새 CLI 출력 경로와 원시 글자를 사용한다. 빈 결과·VLM 토큰 잘림은 실패로 표시하고 자동 반영하지 않는다. 선택 후보는 복사하거나 현재 커서에 삽입하며 선택된 기존 글자를 덮어쓰지 않는다. 삽입은 실행 취소할 수 있다.
- 재인식 창은 소유한 프로세스만 취소/종료하고 완료된 이전 후보·원본·편집본을 유지한다.
- TASKS/PLAN의 이전 다음 단계와 사용자 최신 합의가 달라 최신 순서로 통일했다. 원인은 새 요구사항 반영이며 기존 완료 구현이 취소된 것은 아니다. 내장 텍스트 직접 추출은 승인된 후속 기획이며 이번에 구현한 기능으로 표시하지 않는다.

## 실행 확인

- 주 화면 Offscreen 실제 프로세스: `sample.pdf` 1페이지, GPU·200 DPI·Kiwi로 실행 완료. 저장 설정 200 DPI 및 미리보기의 실제 검출 영역 21개·편집기 결과 표시를 확인했다.
- 저장된 17페이지 전체 입력 PNG로부터 로컬 검증용 1페이지 PDF를 만들고 누락 대사 부분만 선택했다. 원본 전체 PDF를 다시 연 시험이 아니며 이미지 PDF 변환의 영상 차이가 있을 수 있다.
- 실제 재인식 비교 창에서 같은 영역을 GPU 200 DPI / GPU 400 DPI / CPU 200 DPI로 실행했다. 3개 후보 모두 대사 본문을 포함했고 각 출력의 DPI·요청 장치·영역을 확인했다. 200 DPI 전체 크기 915×1427, 400 DPI 1830×2854로 상대 영역 유지도 확인했다.
- 해당 작은 영역의 OCR 처리 시간은 약 0.30/0.36/0.29초(모델 초기화 제외)였다. 전체 문서 성능이나 CPU/GPU 속도 비교를 보장하지 않는다. DPI 증가 후에도 첫머리의 반복 글자 오인식은 남았다.
- 완료 신호가 Qt `QDialog.finished` 이름과 충돌해 실제 후보 등록이 누락되는 문제를 실제 실행에서 발견하고 콜백을 `process_finished`로 분리했다. 회귀 검사도 QProcess 완료 신호를 직접 전달하도록 보완했다.
- 1,380×880 주 화면·녹색 검출 다각형·비교 창의 후보 이미지/문자 배치를 렌더링해 확인했다.

## 회귀 검사와 제한

합성 PDF·이미지·대역으로 DPI 인자/기본값 복원, 원시 좌표/확대/페이지 전환, 잘못된 상대 좌표 거부, 역방향 재인식 드래그의 추출 범위 보존, 별도 작업 인자/저장 경로, 토큰 잘림 거부, 기존 선택 텍스트 보존과 삽입/실행 취소를 검사했다. 실제 소유 프로세스 취소도 확인했다.

전체 pytest 195개와 Python 42개 Docstring·Ruff·포맷 검사가 통과했다. 문서 39개의 로컬 링크 186개와 Git 공백 검사도 확인했다.

이번에 실제 실행한 모델은 PP-OCRv5이며 임의 영역의 VL/Qwen 정확도·CPU/GPU 전체 페이지·400/600 DPI 장시간 사용·다양한 문서/회전과 경계 글자의 일반 품질은 추가 평가한다. Windows 실제 마우스 조작은 수행하지 않았고 Offscreen 화면에서 실제 OCR 프로세스를 실행했다. Markdown 구조 블록 검출 표시·후보 목록 재불러오기·문장 자동 삽입 위치 추정·내장 텍스트 직접 추출·EXE 배포는 이번에 제공하지 않는다.
