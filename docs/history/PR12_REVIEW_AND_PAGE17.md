# PR #12 리뷰 수정과 17페이지 보정 누락 재발

날짜: 2026-10-13. CodeRabbit의 실제 지적 1개를 현재 구현과 대조해 타당하다고 판단하고 같은 PR에 반영했다. 사용자가 제시한 본문의 재발도 로컬 저장 결과에서 확인했다. 실제 본문·사전 내용·이미지는 Git에 복사하지 않는다.

## 리뷰: 문단 내부 빈 줄의 재분할

OCR line에 내부 빈 줄이 들어갈 수 있고 복원 결과는 이를 하나의 좌표 문단으로 보존한다. 기존 통합 함수는 문자열을 다시 `\n\n`으로 분할해 문단 수가 다르다고 오류를 냈다. 연결 옵션이 꺼진 재보정도 영향을 받으므로 지적은 타당하다.

문단 객체의 텍스트를 직접 읽고 Kiwi의 보정 전·사전 미적용 결과도 문단별 문자열 배열로 저장하도록 수정했다. 제안의 취지는 채택했지만 예시 코드는 배열의 원소 형식이 맞지 않아 그대로 적용하지 않았다. 이전 보정 형식은 원문 글자 순서와 생성 구분자에 맞춰 정렬하며 근거가 부족하면 명시적 오류를 낸다. 보정 비교의 공백 외 글자 변경도 거부한다.

## 실제 재발 원인

최근 `output/gui-8a0ad716c580/result/page-017.json`은 원시 영역 24개이며 본문 줄 19와 별도의 작은 따옴표 영역 20이 같은 높이에 겹쳤다. 작은 영역은 본문의 오른쪽 끝이 아니라 시작 부분에 있었다. 기존의 작은 닫는 부호 연결 조건을 만족하지 않아 페이지 전체가 `overlapping_rows_or_columns`로 보존됐고 Kiwi도 실행되지 않았다.

이전 정상 실행은 같은 페이지의 22개 영역을 인식했다. 두 실행은 GPU·300 DPI·동일한 200단어 사전이며, 이전은 전체 페이지이고 재발 실행은 상대 영역 아래 경계가 약 0.911이었다. 설정과 검출 차이는 확인했지만 모델 내부에서 추가 검출이 생긴 정확한 이유까지 단정하지 않는다. 기존의 오른쪽 닫는 부호 수정이 제거된 것은 아니다.

## 수정: 드문 겹침의 정상 구간 복원

같은 높이의 모호한 블록은 줄·글자를 그대로 보존하고 나머지 연속 정상 구간만 문단 복원한다. 겹침 관련 영역이 최대 4개이면서 유효 영역의 25% 이하일 때만 부분 복원을 시도한다. 다단처럼 겹침이 많거나 좌표가 없으면 기존 전체 보존을 유지한다. 이 수치는 보수적인 초기 기준이며 모든 문서를 정확히 분류한다는 근거가 아니다.

부분 복원 문단의 `geometry_applied=false`에는 Kiwi·사전 공백 보정을 적용하지 않는다. 페이지 결과에 `partial_geometry_applied`, 문단별 적용 여부, `overlapping_region_preserved`와 원시 줄 인덱스, 보정 제외 문단 배열을 기록한다. 원시 lines·좌표·신뢰도는 변경하지 않는다. GUI 완료 안내에 부분 복원 페이지 수를 표시하며 이런 페이지의 페이지 간 연결은 확인 대상으로 보존한다.
