# 짧은 어미 줄의 문단 분리 수정

기준일: 2026-10-13. PR #12 병합 이후 사용자가 제보한 18페이지의 짧은 어미 분리를 별도 작업으로 수정했다. 실제 원문·PDF·OCR 출력·사용자 사전은 Git에 포함하지 않는다.

## 원인

저장된 200 DPI 결과의 앞줄 영역 높이는 32px, 뒤의 짧은 종결 어미 영역은 43px였다. 비율 1.34375가 기존 다른 글꼴/문단 판정 기준 1.3을 넘어 분리됐다. 앞줄의 짧은 길이·다음 줄 들여쓰기·큰 간격은 원인이 아니었다. 일반 한글 경계는 기본적으로 모호한 공백 연결이어서 어미 조각의 공백 없는 연결도 보완해야 했다.

## 제한된 수정

- 앞줄의 마지막 두 글자가 한국어 및 `았/었/였/겠/했/됐/이`이고 다음 줄은 `다`와 종결/닫는 부호만 있는 경우를 검사한다.
- 앞줄이 본문 폭의 80% 이상까지 이어지고, 뒤의 작은 영역 너비가 대표 높이의 2.5배 이하이며 본문 왼쪽 정렬·앞줄과의 좌우 차이·보통 줄 간격·최대 1.6배 높이 비율을 모두 만족해야 한다.
- 기존 높이 차이에 의한 분리만 예외 처리한다. 큰 간격·들여쓰기·목록·짧은 앞줄은 기존 경계를 유지한다. 더 큰 글꼴 차이와 다단/좌표 누락도 기존 보존 경로를 따른다.
- 공백 없이 이어 붙이되 글자·문장부호를 생성/치환하지 않는다. `short_ending_continuation`에 원시 줄 인덱스·확인 필요를 기록한다. 페이지 사이 연결 규칙은 이번에 바꾸지 않았다.

## 검증

- 합성 사례의 어미·닫는 부호 연결, 원시 글자·좌표·인덱스 보존을 확인했다.
- 이미 종결된 문장·이어지는 다른 문장·큰 간격·들여쓰기·큰 글꼴 차이·목록·짧은 앞줄을 잘못 합치지 않는지 확인했다.
- 관련 문단/띄어쓰기/PR #12 회귀 검사 52개 및 전체 pytest 205개 통과. Python 42개 Docstring·Ruff·포맷 검사 통과.
- 최신 저장 18페이지를 같은 사용자 사전으로 새 출력 폴더에서 재보정했다. 대상 어미가 본문과 같은 문단으로 이어졌고 원시 `lines`는 이전 결과와 완전히 같았다. 기존 결과나 사용자 편집 파일은 바꾸지 않았다.
- 이번 실행은 저장 JSON 재처리이며 OCR 모델 재실행·실제 GUI 조작·다양한 자료/DPI·모든 한국어 어미의 언어학적 판정은 수행하지 않았다.

## 남은 범위

한 글자 `다` 조각에도 우연히 규칙이 맞을 가능성이 있어 확인 필요로 기록한다. 다른 어미·단어 조각·실제 글꼴이 다른 짧은 제목은 추가 품질 평가가 필요하다. 일반적인 어미 분석·문자 교정 모델을 도입하지 않았고 사용자 사전은 공백 보정에만 적용한다. 후속 작업 순서는 [개발 목록](../TASKS.md)을 따른다.
