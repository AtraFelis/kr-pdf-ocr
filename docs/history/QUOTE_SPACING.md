# 인용문 여는 부호의 공백 수정

날짜: 2026-10-13. 사용자가 인용문 띄어쓰기가 제대로 되지 않는다고 알렸고 실제 결과 문장을 확인했다. 현재 Kiwi에서는 인용문 내부 공백은 보정했으나 앞 한글과 여는 작은따옴표 사이 공백은 넣지 않았다. 저장된 동일 본문의 OCR 결과에서도 같은 경계 문제를 확인했다. 인용문 내부 보정 전체가 생략되는 오류로 단정하지 않았다.

## 변경

Kiwi 공백 보정 뒤에 짝이 맞는 한글 인용문의 여는 부호 경계만 보완한다. 바로 앞 글자와 인용 시작이 한글인 경우 공백을 넣고 닫는 부호 뒤 조사와 원래 문장부호를 보존한다. 짝 없는 부호·영문 아포스트로피·이미 공백이 있는 경계는 변경하지 않는다. ASCII·곡선 부호 혼용과 낫표를 지원한다. 글자를 추가·교체하지 않으며 기존 공백 외 문자 보존 검사도 적용한다.

사용자 사전 적용 결과와 미적용 비교 결과에 같은 규칙을 사용한다. `spacing.korean_quote_boundaries=true`로 처리 정책을 기록한다. 좌표가 없어 보정하지 않는 VLM 출력·Markdown에는 새 규칙을 일괄 적용하지 않는다.

## 확인 범위

- 합성 검사 14개를 추가했다. 부호 조합 7개, 영문·짝 없는 부호·이미 있는 공백 등 보존 사례 6개, 실제 Kiwi 내부 보정과 경계 보완 사례 1개를 확인했다.
- 기존 사용자 사전 검사를 포함한 관련 검사 32개가 통과했다. 전체 135개 검사와 Python 34개 Docstring·Ruff·포맷 검사를 통과했다.
- 기존 49페이지 원시 JSON을 실제 Kiwi로 새 폴더에 재처리해 여는 부호 앞 공백, 닫는 부호 뒤 조사, 원시 lines와 공백 외 글자 보존을 확인했다. 모델 OCR은 이번에 다시 실행하지 않았다.
- 실제 결과는 Git 제외 경로 `output/quote-spacing-fixed-8cdc89261065/`에 저장했다. 실제 본문을 테스트·문서에 복사하지 않았다.

모든 인용·코드·불완전한 따옴표의 의미를 분석하는 기능은 아니다. OCR 문자 오류와 문장부호 누락은 생성으로 복구하지 않으며 추가 평가 대상으로 유지한다.
