# 기능 구현·검증 기록

기능 사용법 문서에 작성되어 있던 실행·검증 결과를 분리한 기록이다. 문서 정리일은 2026-10-12이며 각 과거 검증의 수행일을 새로 확정한 것은 아니다. 현재 동작과 제한은 각 기능 사용법과 [개발 목록](../TASKS.md)을 참조한다.

## 문단 복원과 띄어쓰기 보정

기능 사용법: [문단 복원과 로컬 띄어쓰기 보정](../TEXT_RESTORATION.md).

샘플 첫 페이지는 제목과 하단 쪽수를 포함한 7개 문단으로 구분했다. `output/paragraph-run-01`은 규칙 기반 복원, `output/paragraph-spacing-01`은 선택적 보정을 추가한 결과다. 한자 병기를 같은 방식으로 제외한 정답 초안 비교에서 공백 포함 오류율은 원시 결과 약 15.79%에서 보정 결과 약 3.09%로 감소했다. 공백 무시 오류율은 둘 다 약 1.92%였다.

이는 한 페이지에 대한 결과이며 연속 공백을 한 칸으로 정규화한 문자 편집 거리다. 문단 경계 정확도나 일반적인 OCR 정확도를 뜻하지 않는다. 원래 OCR의 문자·문장부호 오류는 그대로 남았다.

## 페이지·영역 선택

기능 사용법: [페이지·영역 선택](../PAGE_SELECTION.md).

합성 PDF로 범위·제외·빈 선택, 200~800px 환산, 해상도 변경, 90도 회전, 페이지별 우선 적용, 원본 좌표 보존과 통합 TXT를 확인했다. 실제 샘플은 1~3페이지 중 2~3을 제외하고 1페이지의 세로 20~90%만 처리했다. 제목과 하단 쪽수가 제외되고 본문 5개 문단이 저장됨을 확인했다. 결과는 `output/region-run-01`이다.

## 데스크톱 화면

기능 사용법: [데스크톱 프로그램](../DESKTOP_APP.md).

자동 UI 검증으로 역방향 드래그, 확대 전후 선택 비율, 페이지 체크와 영역 적용, 편집 결과의 UTF-8 저장, 덮어쓰기·원본 PDF 보호, 취소·실패 시 완료 결과 보존을 확인했다. 실제 샘플 첫 페이지를 화면에서 VL 1.6으로 인식하고 결과 표시와 TXT 저장까지 확인했다. 화면 이미지를 렌더링해 한글 글꼴과 주요 컨트롤 배치를 검토했다. 사용자 PC에서 모든 창 크기·고해상도 화면과 긴 문서에 대한 장시간 사용 검증은 남아 있다.

### 색상 수정

색상 수정은 어두운 초기 Qt 팔레트를 설정한 offscreen 환경에서 빈 화면·합성 PDF를 연 화면·처리 중 비활성 컨트롤·모델 선택 메뉴를 렌더링해 확인했다. 이번 색상 수정에서는 자동 테스트와 OCR 모델을 다시 실행하지 않았다. 실제 Windows 다크 모드에서 재실행한 화면 확인은 남아 있다.

### CPU와 GPU 선택

같은 샘플 첫 페이지를 화면에서 PP-OCRv5로 실행한 처리 구간은 CPU 약 7.60초, GPU 약 1.50초였다. 300 DPI, 전체 영역, 문단 복원·Kiwi 보정 설정이 같으며 모델 준비·렌더링·출력 저장 시간은 제외한다. 한 페이지 기준으로 전체 문서의 속도를 보장하지 않는다. 두 결과에 한 글자 차이가 있어 장치 변경 후에도 원문을 확인한다.

장치 선택 추가에서는 CPU 안내·Qwen CPU 추가 안내·GPU 안내 화면을 렌더링했고, 실제 샘플 첫 페이지를 GUI에서 CPU와 GPU로 실행해 완료·장치 기록·결과 표시를 확인했다. VL 1.6의 명시적 GPU 실행도 완료했다. Ruff·포맷·두 환경의 의존성 검사는 통과했다. 이번 변경에서는 pytest 테스트 모음을 실행하지 않았다. VLM의 전체 페이지 CPU 처리 시간과 모든 장치별 취소·실패 조건 확인은 남아 있다.

환경 분리 과정과 초기화·메모리 기록은 [OCR 실행 기록](OCR_SETUP.md#cpugpu-장치-선택-추가-2026-10-12)을 참조한다.
