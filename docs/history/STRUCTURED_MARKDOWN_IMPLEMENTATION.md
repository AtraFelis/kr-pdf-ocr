# 구조 분석·Markdown 첫 연결 기록

날짜: 2026-10-13. 현재 사용법과 제한은 [Markdown 출력](../MARKDOWN_EXPORT.md)을 참조한다.

## 구현

공식 v1.6 배치 분석·인식 파이프라인을 기존 선택 페이지·영역·장치 옵션에 연결했다. 원시 블록·위치와 Markdown·이미지를 저장하고 페이지별 고유 이미지 이름으로 통합한다. 공식 변환기 결과를 사용하며 TXT를 단순히 `.md`로 바꾸지 않는다. 기본 머리말·각주 제외를 끄고 차트는 이미지로 남긴다.

GUI에 명시적 출력 선택, Markdown 원문·미리보기, 새 이미지 폴더와 상대 링크 저장을 추가했다. 결과 형식을 다음 작업 선택과 분리하고 원본 PDF·기존 출력 보호를 유지했다. 미리보기는 네트워크·결과 외부 파일을 읽지 않도록 제한했다. TXT의 Kiwi·사전·병기 한자 필터는 구조 출력에 적용하지 않는다.

## 환경 구성과 확인

- 기존 OCR 두 환경을 유지하며 `.venv-doc-parser`를 새로 구성했다. PaddleOCR 3.6.0 / PaddleX 3.6.1 / PaddlePaddle-GPU 3.2.2, PyTorch 없이 설치했다. 전체 의존성을 잠금 파일로 남기고 pip check에서 충돌 없음 확인.
- 공식 PP-DocLayoutV3 리비전 `241f8bdfc77a7c7bee915a5057aaee58c235a8d3`, VL 1.6 리비전 `c5630abae1d940eafe0697512a0325494b02ab42`를 내려받았다. 모델 파일은 Git 제외다. 모델 카드 Apache-2.0 고지를 확인했다.
- Python 소켓 연결을 차단한 상태에서 CPU와 GPU의 전체 파이프라인 초기화가 성공했다. 배치 모델·VL 모델 가중치를 로컬에서 불러왔다. 초기화 로그는 `output/structure-runtime*.log`에 있다. 실제 문서 인식 성공을 뜻하지 않는다.
- 초기 캐시가 사용자 홈을 가리키던 오류는 프로젝트 `.cache/structure`로 수정했다. 로컬 패키지 등록 중 샌드박스 임시 경로 접근 오류는 승인된 전용 환경 설치로 재시도해 해결했다. 전역 환경·기존 OCR 환경을 변경하지 않았다.
- 공식 설치 코드에서 결과의 JSON·Markdown·이미지 인터페이스를 대조했다. 화면의 합성 제목·본문·표·수식 원문을 offscreen으로 렌더링해 원문/미리보기 배치를 확인했다.
- Docstring·Ruff·포맷은 Python 33개 파일에서 통과했고 문서 링크·앵커 99개와 공백 검사도 통과했다. 실제 PDF 인식·저장 검증 전 상태를 표시해 초안 PR로 올린다.

## 미실행·추가 검증

이번 작업에서는 테스트 추가·pytest·실제 PDF 구조 인식을 실행하지 않았다. 구조 인식부터 이미지 묶음 저장까지의 종단 동작, CPU/GPU 인식·성능·메모리, 표·수식·읽기 순서·이미지 링크·경계 문자·취소·부분 실패의 자동 회귀 검증이 남아 있다. 개발 목록에서 검증 항목은 완료 처리하지 않는다. 실제 DPI·화면 크기·Markdown HTML 표현·수식 렌더링 확대도 후속 작업이다.

후속 우선순위는 합성 또는 배포 가능한 표·차트·다단 PDF와 정답 구조로 검증하는 것이다. 페이지 간 표 병합·제목 재구성·배포는 그 이후에 진행한다.

## 후속 확인

사용자 제공 샘플의 실행·저장·취소와 미리보기 수정·회귀 검증은 [별도 기록](MARKDOWN_SAMPLE_VALIDATION.md)에 추가했다. 위 미실행 상태는 첫 연결 시점의 기록이다.
