# 오류 샘플의 문단·띄어쓰기 보정 중단 수정

날짜: 2026-10-13. 사용자 제공 `samples/input/sample_ocr_err.pdf`의 2페이지 오류를 재현했다. PP-OCRv5 GPU, 기본 300 DPI, 전체 페이지 입력으로 원시 인식 뒤 문단 복원과 선택적 로컬 Kiwi 보정을 비교했다. 실제 문서·추출 본문·좌표 결과·정답은 Git 제외 경로에만 보관한다.

## 확인한 원인

원시 인식은 25개 영역을 반환했다. 마지막 대사 줄의 닫는 따옴표가 13×13px의 별도 영역으로 분리돼 높이 약 51px인 본문 줄과 겹쳤다. 기존 문단 복원은 이를 `overlapping_rows_or_columns`로 판단해 페이지 전체를 원래 줄 형태로 보존했다. geometry_applied=false이므로 Kiwi도 실행하지 않아 줄바꿈과 공백 오류가 그대로 남았다. OCR 문자 인식 오류와 후처리 중단은 별개다.

이 파일은 이전에 조사한 동일 본문의 다른 출력과 구분한다. 이번 제공 파일에서 현재 설정으로 재현한 원인이다.

## 수정

같은 줄 오른쪽에 붙은 작은 닫는 문장부호만 좌표를 이용해 유일한 본문 후보에 연결한 뒤 기존 겹침 검사를 수행한다. 원본 줄 텍스트·좌표·신뢰도를 그대로 두고 연결한 모든 원본 줄 인덱스와 `attached_closing_punctuation` 검토 항목을 기록한다. 글자나 문장부호를 생성·교체하지 않는다.

높이·너비가 크거나 본문 끝에서 멀거나 본문 내부에 있는 부호, 여는 부호·일반 문자, 후보가 두 개 이상인 경우는 연결하지 않는다. 실제 다단·좌표 누락·미해결 겹침은 기존 보존 정책을 유지한다. 전체 페이지를 무조건 연결하거나 겹침 검사를 제거하지 않는다.

## 검증 결과와 한계

- 수정 전 원시 OCR과 Kiwi 재처리에서 2페이지의 복원·공백 보정 제외를 확인했다.
- 수정 후 저장한 동일 원시 JSON으로 재처리해 geometry_applied=true, 문단 14개, 부호 연결 1개, Kiwi 공백 변경 제안 13개를 확인했다.
- GPU로 1~2페이지를 다시 인식한 뒤 실제 Kiwi로 재처리했다. 각각 24/25개 원시 줄, 13/14개 문단이며 두 페이지 모두 복원·Kiwi가 적용됐다. 두 페이지의 공백 외 글자, 원시 lines와 모든 줄 인덱스가 보존됐다. 원본 PDF와 기존 결과는 변경하지 않았다.
- 합성 검사 8개를 추가했다. 따옴표 연결·원시 결과/인덱스 보존, 멀거나 내부·크거나 여는 부호·일반 문자 보존, 다중 후보와 다단 배치 유지, 실제 Kiwi 연결을 확인했다. 전체 121개 검사와 Python 34개 Docstring·Ruff·포맷 검사가 통과했다.
- 실행 결과는 `output/ocr-error-verified-60aa5e58b0ea/`와 같은 이름의 `-spacing/`, 수정 전후 비교는 `output/ocr-error-*`에 있다.

일부 글자 치환·문장부호 누락·고유명사와 일반 단어의 공백 오류는 남아 있다. 이번에 정답 전체 대조·CER·CPU 실행·다양한 DPI를 평가하지 않았다. 모든 겹침이나 좌표 누락에서 정상 영역을 부분 복원하는 기능과 상세 화면 안내는 추가 작업이다. 새로운 문자 교정 모델은 아직 연결하지 않았다.
