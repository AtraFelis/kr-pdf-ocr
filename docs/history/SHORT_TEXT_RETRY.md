## 구현과 판단

원시 결과를 유지하고 여백·배율을 달리한 영역을 재인식해 사람이 비교할 후보를 제공한다. 초기 실험에서 문자 인식기만 직접 호출했을 때 오류가 증가해 기존 검출·인식 파이프라인을 다시 사용하는 방식으로 변경했다. 이미지에서 단일 줄을 찾지 못하면 실패로 표시한다. 자동 교정이나 점수만으로 원문을 교체하는 기능은 추가하지 않았다.

CLI와 GUI 옵션·후보 비교 창을 연결했다. 이미지·원시 인식·후보·점수·실패를 보여주고 선택 문장을 복사한다. 사용자가 원문 편집에서 채택한다. 선택 영역 경계를 벗어나지 않으며 원시 줄·좌표와 입력/전체 좌표 대응을 유지한다. 기본 페이지 결과는 후보 실행 전에 저장하므로 취소·후보 실패 시 기본 결과가 남는다.

## 실제 실행

- 오류 샘플 GPU 1~2페이지: 원시 24/25줄, 후보 선정 9/13줄, 조건별 18/26개 후보. 단일 줄 검출 실패는 7/10개 조건이다. 후보 실패를 기본 OCR 실패나 성공 후보로 표시하지 않았다.
- 원본에서 마침표가 있는 문장에 기본 OCR의 마침표가 빠졌고 재인식 조건에서 회복되는 사례를 확인했다. 다른 조건에서는 마침표 누락·글자 오류가 증가하는 사례도 확인했다. 모든 오류를 해결했다고 표현하지 않는다.
- 공개 합성 문장 `응?`을 맑은 고딕 12/16/20px로 만들고 GPU 모델로 검사했다. 20px에서 기본 인식 `\\?`를 두 재인식 조건이 `응?`으로 회복했다. 16px는 유지했고 12px는 원문보다 나빠졌다. 합성 사례의 효과이며 실제 문서 전반 정확도를 보장하지 않는다.
- CPU는 오류 샘플 2페이지의 상대 영역 `[0.10,0.82,0.25,0.86]`을 실행했다. 원시 2줄과 재인식 후보 생성 경로를 확인했다. CPU 전체 문서 성능 비교는 수행하지 않았다.
- 실제 OCRWindow에서 GPU 1~2페이지·Kiwi·재인식 옵션을 실행해 후보 44개와 비교 버튼·창·이미지/원문/후보/실패 표시를 확인했다. 재인식 시간은 페이지별 약 0.69/0.85초였다. 이 환경의 한 번 실행이며 일반 성능 수치로 사용하지 않는다. 실제 PDF·PNG·출력·로그는 Git 제외 폴더에만 보관했다.

## 자동 검사와 제한

합성 검사 9개를 추가했다. 선정 기준 5개, 경계 여백/확대·실패·원시 결과 보존, 최대 후보 수·좌표 누락, 비교 창의 성공 후보 복사/실패 표시/파일 보존, 미지원 CLI 조합을 확인했다. 전체 144개 검사와 Python 37개 Docstring·Ruff·포맷 검사를 통과했다.

고유명사·문자 교정 모델, 전체 정답/CER, 원래 검출에서 완전히 누락된 줄, 원본 PDF 고해상도 재렌더링 비교, 다양한 스캔/DPI·CPU 전체 성능은 후속 평가다. 이번 배율은 입력의 재표본화다. 사용자 요청에 따라 기능 검증·푸시·PR 본문 갱신 후 Draft를 해제하며 병합은 수행하지 않는다.
