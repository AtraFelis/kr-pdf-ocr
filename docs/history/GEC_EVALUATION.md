# gec_kr 로컬 비교 평가와 도입 보류

날짜: 2026-10-13. 사용자가 다음 개발 단계인 한국어 문자 교정 비교 평가를 승인해 수행했다. 앱의 자동 보정·편집 동작은 변경하지 않았다.

## 출처·환경

- [공식 모델 카드](https://huggingface.co/Soyoung97/gec_kr)와 [고정 리비전 파일](https://huggingface.co/Soyoung97/gec_kr/tree/c4a70d9f832fa25e4672aa4ba01c1d88f7787115)을 확인했다. KoBART 계열 `BartForConditionalGeneration`, 가중치 약 496MB이며 리비전은 `c4a70d9f832fa25e4672aa4ba01c1d88f7787115`다.
- 카드와 파일 목록에 명시적인 라이선스가 없고 카드의 공식 GitHub 링크는 조회 시 404였다. 배포·제품 사용 조건은 미확인이다. 파일은 로컬 평가용으로 다운로드했고 저장소·배포본에 포함하지 않는다.
- Windows 11, Python 3.12.14, torch 2.9.1+cu128, transformers 5.19.0, Kiwi 0.24.0. 기존 `.venv`를 사용하며 추가 설치·잠금 파일 변경은 없다. GPU는 RTX 5070, CPU는 AMD64 Family 26 Model 68 Stepping 0·논리 CPU 16개·Torch 스레드 8개다.
- CPU/GPU 모두 FP32. 카드 예제의 BOS/EOS 처리·빔 4·반복 페널티 2.0·128 토큰 출력 상한을 사용하고 샘플링은 끈다. 긴 입력·빈 후보·출력 상한 도달은 거부하며 원문은 그대로 둔다. 가중치는 PyTorch의 weights_only 경로로 로드한다.

## 자료·결과

직접 작성한 합성 사례 20개에 문자 오류·공백·마침표/물음표/말줄임표·짧은 대사·가상의 이름·숫자·영어를 포함했다. 정상 9개, 오류 11개다. Kiwi는 사전을 적용하지 않은 공백 보정이며 기존 앱의 전체 문단/사전 경로와 구분한다.

CPU/GPU의 gec_kr 단독·Kiwi 후 gec_kr 후보가 20개 모두 동일했다. 각 경로에서 `ac` 사례는 빈 결과/토큰 상한 실패로 거부됐으며 `응?`으로 회복되지 않았다. 실패 1건을 숨기거나 성공 사례만의 분모로 전체 성능을 비교하지 않았다.

- 원시 입력: 정확 일치 9/20, 공백 정규화 CER 18/278(6.47%).
- Kiwi: 정확 일치 11/20, 정상 문장 변경 1/9, 오류 사례 개선 4/11·악화 1/11.
- gec_kr 단독: 성공 19/20·정확 일치 10/20, 정상 문장 변경 2/9, 성공한 오류 10개 중 개선 6개·악화 0개.
- Kiwi 후 gec_kr: 성공 19/20·정확 일치 11/20, 정상 문장 변경 3/9, 성공한 오류 10개 중 개선 6개·악화 1개. Kiwi에서 분리된 가상의 연구소 표기가 그대로 남았다.
- 실패 후보를 원시 입력으로 유지한 전체 20개 기준 CER은 Kiwi·gec_kr·Kiwi 후 gec_kr 모두 14/278(5.04%). 공백 제거 CER도 세 경로 모두 9/229(3.93%)로 원시 입력과 동일했다. 일부 글자 오류 개선이 정상 글자의 변경과 상쇄됐다.

`맑슴니다 → 맑습니다`, `밖으러 → 밖으로`는 개선됐다. 핵심 사례 `훌륨한 → 훌륭한`은 실패했고 마침표·물음표·말줄임표 누락 3개도 회복하지 않았다. 정상 문장의 `시작한다 → 시작된다`, `UTF-8로 → UTF-8에` 변경은 공백만의 변경이 아니므로 자동 반영할 수 없다. 이 예제들은 직접 작성한 합성 자료다.

## 시간·메모리

최종 비교 실행의 gec_kr 단독 20회 생성 시간 합은 GPU 약 0.90초, CPU 약 2.79초다. Kiwi 후 gec_kr 경로는 Kiwi 시간까지 포함해 GPU 약 1.51초, CPU 약 3.56초다. 모델·Kiwi 초기화는 GPU 6.93초/CPU 6.69초, 전체 평가 프로세스의 측정 구간은 GPU 9.72초/CPU 13.44초다.

모델·Kiwi를 함께 로드한 프로세스 RSS 관찰 최댓값은 GPU 약 2,104MiB, CPU 약 1,701MiB다. GPU의 PyTorch 최대 할당은 약 488MiB, 예약은 약 538MiB다. RSS는 20ms 간격 관찰값이며 모든 순간의 피크를 보장하지 않는다. CUDA 지표는 드라이버의 전체 VRAM이 아니다. 반복 벤치마크·워밍업 분리·단독 Kiwi 메모리 측정은 하지 않았으므로 수치를 일반 문서 성능으로 확대하지 않는다.

## 검증·보존

CPU/GPU 전체 합성 자료 실행과 후보 동일성, 모델 다운로드와 소켓 차단 상태의 로컬 추론을 확인했다. 사례별 후보·변경 위치는 `output/gec-cpu-verified-01/`, `output/gec-gpu-verified-01/`에 보관한다. 변경 위치 기록과 집계는 저장 후보에 대한 로컬 후처리로 추가했으며 모델 추론 시간에 포함하지 않았다. 실제 문서나 기존 출력·사용자 편집본은 사용하거나 변경하지 않았다.

Docstring 검사(Python 41개)·Ruff·포맷·Git 공백 검사를 통과했다. Markdown 33개에서 코드 예제 밖 로컬 링크 대상 161개의 존재를 확인했다. 평가 CLI 도움말도 실행했다. 사용자 요청의 모델 비교 실행을 수행했으며 별도 pytest 회귀 검사는 이번에 추가·실행하지 않는다. 기존 152개 검사 통과를 이번 변경의 실행 결과로 사용하지 않는다. OS 방화벽 수준 오프라인·장문 입력·모든 실패 경로·앱 통합은 미검증이다.

## 판단·다음 단계

**현재 설정의 gec_kr을 자동 문자 교정 단계나 배포본에 도입하는 것은 보류한다.** 핵심 OCR 오자·문장부호가 해결되지 않았고 정상 글자 변경도 발생했다. 합성 20개로 모델 전체가 쓸모없다고 단정하지 않는다. 사용자가 선택하는 후보 기능도 이번 작업에서는 연결하지 않았다.
