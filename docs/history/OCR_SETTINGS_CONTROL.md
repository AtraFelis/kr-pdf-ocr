# OCR 검출 기준 사용자 조정 검증

기준일: 2026-10-13. 검출 누락 수정과 같은 PR #12에 사용자 설정을 누적했다. 상세 동작은 [OCR 설정](../OCR_SETTINGS.md)을 따른다.

- GUI 처리 장치 아래에 소수 두 자리 입력을 추가했다. 기본 0.50, 범위 0.01~1.00, 화살표 간격 0.05, 의미·잡음/누락 안내 툴팁을 제공한다.
- 같은 창의 모델·형식 전환 시 값을 유지하고 PP TXT만 활성화한다. 부모 패널 잠금으로 OCR 중에는 값을 변경하지 못한다. 재시작 시 기본값이며 전역 설정 파일은 생성하지 않는다.
- 작은 창에서 설정 항목이 잘리지 않도록 왼쪽 패널에 세로 스크롤을 적용하고 안내 높이·패널 폭을 확보했다. 1,380×880 Offscreen 화면을 렌더링해 검출 입력 표시를 확인했다.
- CLI `--det-box-thresh`와 로컬 엔진에서 유한한 범위를 검사한다. CLI는 미지원 모델/형식 조합을 모델 로딩·출력 생성 전에 거부한다.
- 화면 값은 OCR 시작 시 프로세스 인자로 고정되고 실제 설정은 기존 `summary.json.ocr_settings`에 저장된다. 기존 결과·편집본을 재작성하지 않는다.

## 확인한 항목

- CPU/GPU의 기본·사용자 값·양끝 범위 전달, 인식 글자·신뢰도·좌표 보존 및 단일 줄 재인식 확인.
- NaN·무한대·범위 밖 입력과 미지원 VLM/Markdown 조합의 조기 거부 확인.
- 합성 PDF CLI에서 사용자 입력값과 저장된 설정 일치 확인.
- Offscreen GUI에서 값 유지·형식별 비활성·실행 중 잠금·PP 인자 전달과 Qwen 미전달 확인.
- 관련 검사 66개 및 전체 pytest 186개 통과. Python 41개 Docstring·Ruff·포맷 검사 통과.
- 최종 설정 행 배치·스크롤 폭 변경 후 GUI/Markdown 검사 47개를 다시 실행해 통과했다.
- 실제 `sample.pdf` 1페이지에서 GPU 0.60, CPU 0.45로 CLI 실행 완료 및 각각 저장 설정 일치 확인. 두 실행은 서로 다른 장치와 값이므로 정확도 비교의 근거로 사용하지 않는다.

모델 기본값 설명은 공식 문서와 로컬 PaddleX 설정을 대조했다. 다른 수치의 추가 GUI 조정·자동 최적값 탐색·다양한 문서의 모든 허용 값 품질은 제공하거나 검증하지 않았다. Windows 실제 대화형 조작은 이번에 수행하지 않았으며 Offscreen 화면과 인자 전달을 검사했다.
