# 로컬 한국어 PDF OCR 및 TXT·Markdown 추출 프로그램 기획서

## 1. 프로젝트 개요

한국어 PDF를 로컬 AI 모델로 읽고, 필요한 페이지와 영역의 내용을 추출하는 데스크톱 프로그램을 만든다. 텍스트 중심 문서는 자연스러운 문단의 TXT로, 복잡한 문서는 제목·목록·표·수식·그림 등의 구조를 가능한 범위에서 보존한 Markdown으로 저장한다. TXT와 구조화 Markdown의 첫 연결을 제공하며 샘플의 GPU 실행·저장·취소와 CPU 부분 영역을 확인했다. 일반 문서 품질은 추가 평가한다.

주요 해결 과제는 두 가지다.

- 한국어를 중심으로 영어가 섞인 PDF의 문자 인식 정확도를 높인다. 한국어에 병기된 한자는 TXT에서 제외한다.
- PDF의 시각적인 줄바꿈 때문에 문장이나 단어가 끊어진 상태로 TXT에 저장되는 문제를 해결한다.

사용자는 PDF를 외부 서버에 업로드하지 않고 자신의 컴퓨터에서 처리한다. 첫 버전은 **Windows에서 실행되는 개인용 프로그램**을 기준으로 개발한다.

## 2. 목표와 성공 기준

최종 목표는 한국어 PDF의 내용을 원문에 가깝게 인식하고, 별도의 편집 작업을 최소화하는 것이다.

다만 모든 PDF를 완벽하게 인식하는 것은 보장하기 어렵다. 글꼴, 스캔 품질, 흐릿한 문자, 복잡한 배치 등에 따라 오류가 생길 수 있으므로, **실제 사용할 PDF를 기준으로 정확도를 개선하고 인식이 불확실한 부분을 확인할 수 있게 하는 것**을 개발 목표로 삼는다.

첫 버전의 성공 기준은 다음과 같다.

- 한국어·영어가 섞인 PDF를 로컬에서 OCR할 수 있다. 한자 병기 부분은 제외하되 한국어 본문은 보존한다.
- 사용자가 지정한 페이지와 영역만 추출할 수 있다.
- 문단 내부의 불필요한 줄바꿈을 제거한다.
- 실제 문단 구분과 제목·목록의 구조를 가능한 한 유지한다.
- 사용자가 선택한 고유명사 사전을 띄어쓰기 보정에 활용하고, 적용 전후의 고유명사 표기와 일반 문장 품질을 비교할 수 있다.
- 결과를 확인하고 수정한 뒤 UTF-8 TXT로 저장할 수 있다.
- 복잡한 문서에서는 구조화된 Markdown과 필요한 로컬 이미지 파일을 함께 저장할 수 있다(추가 개발 목표).

## 3. 핵심 기능

### 3.1 PDF 불러오기와 미리보기

파일 선택 또는 드래그 앤 드롭으로 PDF를 불러온다.

화면에는 전체 페이지 수, 페이지 목록, 선택한 페이지의 미리보기를 표시한다. 사용자는 미리보기를 확대·축소하거나 페이지를 이동할 수 있다.

암호가 걸렸거나 손상된 PDF를 불러오면 원인과 필요한 조치를 안내한다.

### 3.2 로컬 AI OCR

프로그램에 포함된 OCR 모델을 사용해 PDF 페이지의 문자를 인식한다. 모델 실행과 문서 처리는 로컬에서 수행한다.

필수 인식 대상은 다음과 같다.

- 한국어 본문
- 본문에 섞인 영어와 숫자
- 한국어에 병기된 한자는 인식 정확도 목표에서 제외하고 TXT에서 제거한다. 독립 한자는 임의로 삭제하지 않고 확인 대상으로 둔다.
- 일반적인 문장부호와 기호

OCR 결과에는 텍스트뿐 아니라 **문자의 위치, 줄의 위치, 읽기 순서, 인식 신뢰도**를 가능한 범위에서 보존한다. 이 정보는 문단 복원과 영역 선택에 사용한다.

한자 제외는 한국어 바로 뒤의 한자 또는 한국어 뒤 괄호 안의 한자처럼 병기 관계가 명확한 경우에 우선 적용한다. 원시 OCR 결과는 별도로 보존한다. 한자가 한글로 오인식된 부분은 단순 문자 필터로 구별할 수 없으므로 한국어를 추측으로 삭제하지 않는다.

인식률을 높이기 위해 페이지 이미지의 해상도 조정과 기울기 보정 등을 적용할 수 있도록 설계한다. GPU가 없는 환경에서는 CPU로 실행할 수 있어야 하며, 처리 속도는 환경에 따라 달라질 수 있다.

> 모델은 처음부터 직접 학습하기보다, 한국어를 지원하는 기존 모델을 프로그램에 탑재하는 방식으로 시작한다. 실제 PDF의 인식 결과를 비교한 후 교체나 추가 학습 여부를 결정한다.

### 3.3 페이지 선택 및 제외

사용자는 다음 방식으로 처리할 페이지를 지정할 수 있다.

- 전체 페이지 선택
- 특정 페이지 선택: `1, 3, 5`
- 페이지 범위 선택: `10-20`
- 혼합 선택: `1, 3, 10-20`
- 선택 범위에서 특정 페이지 제외

페이지 번호는 **PDF 파일 안에서 첫 페이지부터 세는 번호**를 사용한다. 책에 인쇄된 쪽수와 다를 수 있다는 점을 화면에 표시한다.

OCR은 선택한 페이지만 수행해 불필요한 처리 시간을 줄인다.

### 3.4 페이지 내 영역 선택

페이지 전체 또는 지정한 영역의 문자만 추출할 수 있다.

영역은 두 가지 방식으로 지정한다.

- **마우스 선택:** 미리보기 위에 사각형을 그린다.
- **수치 입력:** 왼쪽·위쪽·오른쪽·아래쪽 좌표를 입력한다.

예를 들어 페이지 이미지의 높이가 1,000px라면, 위에서부터 **200~800px 구간**만 선택해 해당 구간의 글자를 추출할 수 있다. 상하 범위만 지정하면 가로 방향은 페이지 전체를 사용한다.

영역 설정은 다음 범위에 적용할 수 있다.

- 현재 페이지
- 선택한 여러 페이지
- 처리 대상 전체 페이지

내부에서는 영역을 페이지 크기에 대한 상대 좌표로 저장해, 미리보기 확대나 OCR 해상도 변경에도 같은 위치를 선택하도록 한다. 사용자가 입력하는 픽셀 좌표는 기준 이미지 크기와 함께 표시한다.

선택 경계에 걸친 문자는 잘릴 수 있으므로, 영역 미리보기에서 경계가 적절한지 확인할 수 있어야 한다.

### 3.5 줄바꿈 및 문단 복원

PDF에서 같은 문단에 속하는 여러 줄을 TXT에서는 자연스럽게 이어 붙인다.

**원본 OCR 결과**

```text
선 채로 오도가도 못 하게 되어서 운전자는 할 수 없이 제조사
에 수리를 받으려고 전화를 걸었죠.
```

**목표 결과**

```text
선 채로 오도가도 못 하게 되어서 운전자는 할 수 없이 제조사에 수리를 받으려고 전화를 걸었죠.
```

줄바꿈 복원은 다음 원칙으로 처리한다.

- 문단 내부의 시각적인 줄바꿈을 제거한다.
- 줄 끝과 다음 줄 시작이 하나의 단어이면 공백 없이 연결한다.
- 서로 다른 단어이면 필요한 공백을 유지한다.
- 실제 문단 경계는 빈 줄로 구분한다.
- 제목, 목록, 각주 등은 본문과 구분해 줄바꿈을 유지한다.
- 여러 단으로 구성된 페이지에서는 각 단의 읽기 순서를 고려한다.
- 문장부호만으로 문단 끝을 판단하지 않고 줄 간격·들여쓰기·텍스트 위치를 함께 사용한다.

OCR 결과에 문자 위치나 띄어쓰기 정보가 충분하지 않으면 단어 연결이 모호할 수 있다. 이런 부분은 확인 대상으로 표시한다. **문장을 자연스럽게 만들기 위해 원문의 내용을 임의로 바꾸는 방식은 기본 처리에 포함하지 않는다.**

페이지 끝에서 다음 페이지로 이어지는 문단은 별도의 연결 옵션으로 제공한다.

### 3.6 결과 확인 및 TXT 저장

저장하기 전에 원본 페이지와 추출 결과를 함께 볼 수 있다.

사용자는 결과 텍스트를 직접 수정할 수 있으며, 모델이 제공하는 신뢰도 정보를 이용해 인식이 불확실한 부분을 확인할 수 있다.

기본 저장 방식은 다음과 같다.

- 선택한 모든 페이지를 하나의 TXT 파일로 저장
- UTF-8 인코딩 사용
- 문단 사이에 빈 줄 유지
- 저장 위치와 파일명 지정

페이지 구분 표시를 넣는 옵션과 페이지별 TXT 저장은 추가 기능으로 제공한다.

텍스트 중심 문서의 기본 흐름은 PP-OCRv5 → 문단 복원·선택적 Kiwi 보정 → TXT로 정한다. 복잡한 문서의 흐름은 VL 1.6 문서 구조 분석 → Markdown으로 추가한다. 실제 문자 정확도와 처리 속도는 각각 평가하며, 특정 모델이 모든 문서에서 더 정확하다고 단정하지 않는다.

### 3.7 처리 상태 표시

OCR 진행 중에는 진행률, 현재 처리 페이지, 완료 페이지 수를 표시한다.

처리를 취소할 수 있어야 하며, 특정 페이지에서 오류가 나면 해당 페이지와 원인을 알려준다. 이미 완료된 페이지의 결과는 확인하거나 저장할 수 있도록 유지한다.

### 3.8 고유명사 사용자 사전

첫 구현은 사전 관리·Kiwi 등록·저장 OCR 재보정·별도 비교 창을 제공한다. 세부 품질은 합성 사례에서 확인했으며 실제 문서 품질은 추가 평가한다.

인명·지명·회사명·작품 속 용어 등이 띄어쓰기 보정 과정에서 잘못 분리되는 문제를 줄이기 위해 로컬 사용자 사전을 제공한다. 사전은 선택 기능으로 제공하며 미리 모든 단어를 입력하도록 요구하지 않는다. 오류를 발견한 단어를 추가해 다시 보정할 수 있어야 한다.

- 사전을 만들고 이름을 지정하며 단어를 추가·수정·삭제한다.
- UTF-8 TXT의 한 줄에 하나씩 작성한 단어를 가져오거나 내보낸다. 공백이 포함된 이름도 등록한다.
- 문서·작품·분야별로 사용할 사전을 선택하고 적용을 끌 수 있다.
- OCR 시작 전에 사전을 선택한다. 첫 구현에서는 PP-OCRv5 결과를 문단 복원한 뒤 Kiwi 띄어쓰기 보정에 등록 단어를 반영한다.
- 저장된 OCR 결과를 이용해 사전 적용 전후를 비교하고 재보정한다. 결과는 새 파일로 저장해 기존 출력과 사용자 편집 내용을 보존한다.
- 공백을 제외한 글자는 바꾸지 않는다. OCR이 고유명사의 글자를 잘못 읽은 경우 사전을 근거로 자동 치환하지 않는다.
- 일반 단어와 겹치거나 여러 등록 표기가 충돌하는 경우 확인 대상으로 표시한다. 사전이 일반 문장의 띄어쓰기를 악화시키는지도 확인한다.

사전 내용과 문서는 외부로 보내지 않는다. 사용자 사전 파일도 실제 문서와 같은 로컬 개인 데이터로 관리하고 Git에서 제외한다. 사전 적용으로 품질이 개선되는지는 동일한 오류 문장과 정답으로 확인한다.

현재 VL·Qwen의 자체 문단 출력에는 Kiwi 보정을 적용하지 않는다. VLM의 사전 표기 보호나 OCR 인식 단계의 사전 활용은 별도 비교 후 검토한다. 상세 범위와 개발 순서는 [사용자 사전 설계](USER_DICTIONARY.md)를 따른다.

### 3.9 Markdown 구조화 출력

출력 형식을 TXT 또는 Markdown으로 선택한다. TXT 기본값을 유지하고, 복잡한 문서에서는 VL 1.6과 Markdown을 추천한다. 모델 변경만으로 사용자가 선택한 형식이나 보정 옵션을 조용히 바꾸지 않는다. 지원되지 않는 모델·형식 조합은 이유를 안내한다.

Markdown에는 인식한 제목·목록·본문·표·수식과 읽기 순서를 가능한 범위에서 보존한다. 표·차트·그림은 필요한 로컬 이미지와 상대 링크를 함께 저장한다. 차트의 모든 정보를 글자로 복원한다고 보장하지 않으며, 확인되지 않은 숫자·설명을 생성하지 않는다.

VL의 TXT 직접 실행은 그대로 유지한다. Markdown은 공식 v1.6 구조 분석과 원시 블록·이미지 저장을 연결했으며 별도 환경의 CPU·GPU 초기화를 확인했다. 사용자 샘플에서 GPU 실행·저장·취소와 CPU 부분 영역을 확인했으며 일반 문서 품질은 추가 평가한다. TXT의 확장자만 `.md`로 바꾸는 저장은 구조 복원 완료로 취급하지 않는다.

Markdown의 제목·표·수식·코드·그림 블록에는 TXT용 줄 연결이나 Kiwi 보정을 일괄 적용하지 않는다. 추후 본문 보정을 지원할 경우 대상 블록과 적용 범위를 명시한다. 원시 구조 결과와 출력·이미지를 보존하고 저장 덮어쓰기 확인·원본 보호·취소 시 완료 결과 보존은 같은 기준을 따른다.

상세 범위와 모델별 추천은 [모델 안내와 출력 형식 설계](MODEL_AND_EXPORT.md)를 참조한다.

### 3.10 모델 정보 아이콘

첫 구현과 Tab·Space·Escape·초점 복귀 회귀 검증을 제공한다. 모델 선택 옆의 정보 아이콘을 누르면 선택 모델의 권장 문서 종류, 권장 출력 형식, 속도·자원 특성, 현재 앱 지원 범위와 한계를 보여준다. 상세 설명은 상시 표시하거나 모델 변경 시 자동으로 열지 않는다. CPU 선택 시의 기존 자원 사용 안내는 별도로 유지한다.

- PP-OCRv5: 소설·일반 본문처럼 텍스트 중심 문서와 TXT 추출을 우선 추천한다.
- VL 1.6: 표·차트·수식·다단 구조가 있는 문서와 Markdown 추출을 추천한다. 현재 앱의 TXT 경로·공식 Markdown 첫 연결, 샘플 검증 범위와 일반 문서 품질 평가가 남은 상태를 구분한다.
- Qwen3-VL-2B: 이미지·텍스트 혼합 페이지를 읽는 비교 후보로 안내하고 현재 TXT 추출을 추천한다. 구조화 출력 품질은 별도 평가한다.

아이콘은 키보드로 열 수 있게 하고 접근성 이름을 제공한다. 안내를 닫으면 작업 화면으로 돌아오며, 안내를 여는 것만으로 모델·출력 설정이나 OCR 실행 상태가 바뀌지 않는다.

### 3.11 한국어 문자 교정 모델 비교 평가 (예정)

OCR의 글자 치환·누락과 문장부호 오류를 줄이기 위해 선택적 로컬 문자 교정 기능을 평가한다. 현재 Kiwi 경로는 공백만 바꾸며 문자 교정 기능은 아직 구현하지 않았다. 기존 Kiwi·고유명사 사전 정책은 유지하고 별도 교정 단계의 도입 여부를 판단한다.

- 첫 비교 후보는 한국어 교정용으로 학습된 `Soyoung97/gec_kr`이다. SKT 기본 KoBART를 교정 전용 모델과 구분한다. KoGEC는 배포 가중치·라이선스·실행 조건을 확인한 뒤 추가 후보 여부를 결정한다.
- `훌륨한 → 훌륭한` 같은 글자 치환, 공백 누락·과도한 분리, 마침표 누락, 짧은 대사, 고유명사·숫자·영어·정상 문장을 같은 평가 자료에 포함한다. 특정 예제를 잘 고친다고 일반 정확도를 보장하지 않는다.
- OCR 원문과 정답을 비교하고 교정 성공률뿐 아니라 정상 글자·이름·대사 말투를 잘못 변경하는 비율도 평가한다. 인식·공백·문단·문장부호 오류를 구분하며 시간·메모리·모델 버전과 라이선스를 기록한다.
- 자동 덮어쓰기 대신 원문·교정 후보·변경 위치를 제시하고 사용자가 채택할 수 있도록 설계한다. 요약·의역·내용 추가를 허용하지 않으며 원시 결과와 기존 편집본은 보존한다. 문장부호 추정은 원본 확인이 필요한 제안으로 구분한다.
- 첫 평가 범위는 TXT 본문이다. Markdown의 표·수식·제목·코드·이미지 링크에 일괄 적용하지 않는다. 문서와 교정 결과는 외부 서버로 보내지 않는다.
- 기존 교정 모델의 효과가 부족할 때만 배포 가능한 OCR 오류/정답 자료를 확보해 추가 학습을 검토한다. 모델 설치·실험·제품 연결은 각각 실제 결과를 확인한 뒤 진행하며 이번 계획 추가를 구현 완료로 처리하지 않는다.

2026-10-13 기준 PR #8은 병합됐다. 오류 샘플의 작은 닫는 부호로 인한 페이지 보정 중단과 인용문 앞 공백은 수정했고, PP-OCRv5 후보 비교·선택 줄의 VL 1.6/Qwen 재인식·편집기 반영을 제공한다. 다음 작업은 남는 오류를 대상으로 한 `gec_kr` 로컬 비교 평가다. 보정 제외 이유 표시·정상 영역 부분 복원과 다양한 문서의 재인식 정확도 확대는 후속 작업으로 남긴다. 근거와 후보 출처는 [문자 교정 도입 계획](history/TEXT_CORRECTION_PLAN.md), 현재 순서는 [개발 목록](TASKS.md)을 참조한다.

### 3.12 짧은 대사·문장부호 재인식 후보

PP-OCRv5 TXT의 선택 기능으로 짧거나 점수가 낮거나 종결 부호 누락이 의심되는 줄을 여백·배율 두 조건으로 다시 읽는다. 후보와 실패·이미지·입력/전체 좌표를 기록하며 원시 결과·기존 편집 내용을 자동 교체하지 않는다. 비교 창에서 원본 이미지를 확인하고 선택 문장을 복사하거나 편집기의 유일한 일치 구간에 반영한다. 반영은 실행 취소할 수 있고 파일 저장은 별도로 한다. 선택 줄을 VL 1.6·Qwen으로 재인식하는 기능도 제공한다. 점수로 자동 채택하거나 문장부호를 추측 생성하지 않는다. 기능·검증 범위와 상한은 [사용법](SHORT_TEXT_RETRY.md)을 따른다. GPU 실제 샘플·짧은 대사 합성 사례·CPU 부분 영역을 확인했으며 완전히 누락된 줄과 다양한 DPI는 추가 평가한다.

## 4. 사용자 이용 흐름

1. 프로그램을 실행하고 PDF를 불러온다.
2. 미리보기에서 처리할 페이지를 선택하거나 제외한다.
3. 필요한 페이지에 추출 영역을 지정한다.
4. 필요한 경우 고유명사 사전을 선택하거나 오류가 잦은 단어를 등록한다.
5. 모델 설명 아이콘에서 문서별 권장을 확인하고 TXT 또는 Markdown 출력 형식을 선택한다(Markdown은 샘플 실행 검증, 품질 추가 평가).
6. TXT에서는 문단 복원·선택적 사전 보정을, Markdown에서는 구조 분석을 수행한다.
7. 원본과 결과를 비교하고 필요한 부분을 수정한다.
8. 선택한 형식으로 저장한다. Markdown은 필요한 이미지 파일도 함께 저장한다.

## 5. 화면 구성

첫 버전은 하나의 작업 화면을 중심으로 구성한다.

- **상단:** PDF 열기, OCR 실행, 취소, 결과 저장(TXT·Markdown)
- **왼쪽:** 페이지 목록과 페이지 선택 설정
- **왼쪽 설정 영역:** 모델·정보 아이콘·처리 장치·출력 형식·사용자 사전 선택(Markdown은 샘플 실행 검증, 품질 추가 평가)
- **가운데:** PDF 미리보기와 영역 선택
- **오른쪽:** 추출 텍스트와 직접 편집
- **하단:** 진행 상태와 오류 안내

추출 영역은 미리보기 위에 표시하고, 선택된 페이지와 제외된 페이지를 쉽게 구별할 수 있게 한다.

## 6. 구현 방향

프로그램은 다음 역할을 분리해 구현한다.

- PDF 불러오기 및 페이지 이미지 생성
- 로컬 OCR 모델 실행
- 페이지와 영역 선택
- 읽기 순서 및 문단 복원
- 사용자 사전 저장·불러오기 및 띄어쓰기 보정 연결
- 복잡한 문서 구조 분석 및 Markdown·이미지 내보내기
- 결과 편집 및 TXT 저장

OCR 모델을 교체해도 화면과 TXT 저장 기능을 다시 만들지 않도록, 모델의 출력은 공통 형식으로 변환한다.

공통 결과에는 페이지 번호, 텍스트, 위치 좌표, 읽기 순서와 가능한 경우 신뢰도를 포함한다. 문단 복원은 이 결과를 입력으로 사용한다.

OCR 모델과 개발 도구는 실제 한국어 PDF 샘플에서 인식 품질, 실행 속도, 메모리 사용량, 배포 가능 여부를 확인한 뒤 확정한다. 최종 배포본은 필요한 모델을 포함해 문서 처리 시 인터넷 연결이 필요하지 않도록 한다.

## 7. 바이브 코딩 개발 순서

### 1단계: OCR 가능성 확인

실제로 사용할 PDF 몇 개를 준비해 로컬 OCR 모델의 결과를 비교한다.

한국어와 영어, 한자 병기가 있는 문서를 포함하고, 한국어·영어 인식 결과와 위치 정보를 확보할 수 있는지 확인한다. 한자 인식 자체보다 병기 제외 후 한국어 보존을 평가한다. 이 단계에서 기본 모델과 실행 환경을 결정한다.

### 2단계: 최소 기능 완성

PDF 한 개를 불러오고, 지정한 페이지를 OCR한 뒤 TXT로 저장한다.

먼저 전체 처리 흐름을 끝까지 연결해 작동하는 시제품을 만든다.

### 3단계: 페이지 및 영역 선택

페이지 선택·제외와 사각형 영역 선택을 추가한다. 선택한 범위가 결과에 정확히 반영되는지 확인한다.

### 4단계: 문단 복원

불필요한 줄바꿈 제거, 단어 연결, 문단 경계 유지 기능을 구현한다.

개발 중 발견한 오류 사례를 모아 같은 문제가 다시 발생하는지 확인할 수 있게 한다.

고유명사 사용자 사전·모델 정보·구조화 Markdown, PR #8 리뷰 수정·샘플의 보정 중단 수정·짧은 대사 재인식과 후보 반영까지 구현해 병합했다. 다음 순서는 `gec_kr` 로컬 문자 교정 평가 → 평가 결과에 따른 원문 비교·사용자 채택 기능 → 보정 제외 안내·부분 복원 및 문단/구조 품질 확대 → 성능·배포 검증이다. 새 문자 교정 기능의 도입 여부는 평가 후 결정한다.

### 5단계: 사용성과 배포

원본·결과 비교, 직접 편집, 진행률, 취소와 오류 안내를 추가하고 Windows에서 실행할 수 있는 형태로 배포한다.

**각 단계는 작은 기능 단위로 구현하고, 실제 PDF의 결과를 확인한 뒤 다음 단계로 진행한다.**

## 8. 첫 버전에서 집중할 범위

첫 버전은 **한국어 중심의 일반적인 인쇄 문서와 단일 본문 배치**에서 정확한 OCR과 문단 복원을 구현하는 데 집중한다.

텍스트 중심 경로를 먼저 완성한 뒤 VL 1.6의 표·차트·수식·다단 문서 분석과 Markdown 출력을 추가한다. 손글씨·세로쓰기·검색 가능한 PDF·모델 직접 학습은 이후 개선 대상으로 둔다. 복잡한 문서 지원은 대표 샘플에서 구조·읽기 순서·이미지 저장을 확인한 범위만 완료 처리한다.

개발 시작 전에 준비할 가장 중요한 자료는 **실제로 사용할 대표 PDF와 원하는 TXT 결과 예시**다. 이 자료를 기준으로 모델 선택과 문단 복원 규칙의 품질을 판단한다.
