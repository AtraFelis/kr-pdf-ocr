# 모델 안내와 출력 형식 설계

현재 지원: 세 모델의 로컬 TXT 추출·CPU/GPU 선택. **개발 예정:** 클릭형 모델 설명, VL 1.6 구조화 문서 분석, Markdown 출력·이미지 저장. 요구사항은 [기획서](PLAN.md), 작업 순서는 [개발 목록](TASKS.md)을 따른다.

## 문서와 추출 목적별 추천

### PP-OCRv5 한국어

- 권장 문서: 소설·일반 본문·텍스트 중심의 한국어 인쇄 문서. 특히 단일 본문 영역의 다수 페이지 처리.
- 권장 형식: TXT. 줄 위치와 신뢰도를 활용해 문단 복원·선택적 Kiwi 보정·사용자 사전 보정을 연결한다(사용자 사전은 개발 예정).
- 장점: 현재 샘플에서 빠른 처리와 위치 기반 후처리를 확인했다. CPU에서도 실행할 수 있고 GPU를 선택할 수 있다.
- 확인할 부분: 공백 누락·고유명사·문자 오류, 표·차트·복잡한 읽기 순서. 현재 파이프라인의 TXT는 문서의 표 구조를 보존하지 않는다.

### PaddleOCR-VL 1.6

- 권장 문서: 표·차트·수식·그림·다단 등 여러 종류의 요소가 배치된 보고서·논문·복잡한 문서.
- 권장 형식: 구조 분석을 연결한 Markdown. 필요하면 본문 위주의 TXT도 선택한다.
- 장점: 공식 문서 파이프라인은 구조화 결과와 Markdown 저장 경로를 제공한다. 문서 구조를 이용한 추출을 목표로 한다.
- 현재 앱의 범위: Transformers 직접 실행으로 일반 텍스트만 추출한다. 공식 파이프라인·추가 구조 분석 모델·Markdown·이미지 출력은 아직 연결하지 않았다.
- 확인할 부분: 표 셀·수식·읽기 순서·이미지 누락과 모델 생성 오류. GPU 사용을 우선 권장하며 CPU에서는 긴 처리 시간과 메모리 사용을 안내한다.

### Qwen3-VL-2B-Instruct

- 권장 용도: 이미지·텍스트 혼합 페이지의 글자 읽기와 다른 OCR 결과 비교. 기본 모델에서 오류가 많은 일부 페이지의 비교 후보.
- 권장 형식: 현재는 TXT. 구조화 Markdown 지원 여부와 품질은 별도 평가한다.
- 현재 앱의 범위: 로컬 모델에 보이는 글자를 그대로 옮기도록 지시한다. 줄 위치·신뢰도는 제공받지 않아 만들지 않는다.
- 확인할 부분: 원문과 다른 생성·누락·읽기 순서, 처리 시간과 GPU 메모리. 문서 구조 분석·숫자 정확도는 실제 샘플로 확인한다.

추천은 문서 종류·목적·속도·현재 지원 기능을 종합한 사용 흐름이다. 한국어 글자 정확도는 별도 평가한다. 기존 텍스트 샘플에서 PP-OCRv5가 더 빨랐고, 일부 문자·공백 오류 지표는 VL 1.6이 더 좋았다. 세부 조건과 수치는 [모델 선택 기록](history/MODEL_SELECTION.md)과 [실행 기록](history/OCR_SETUP.md)을 참조한다.

## 모델 정보 아이콘

모델 선택 옆에 정보 아이콘을 둔다. 클릭하거나 키보드로 실행하면 선택 모델의 권장 문서·출력 형식·CPU/GPU 특성·현재 지원 기능·한계를 표시한다. 아이콘의 접근성 이름은 '모델 설명'으로 계획한다.

긴 모델 설명은 평소에 표시하지 않는다. 모델 변경 시 설명 창이 자동으로 열리지 않으며, 안내를 열고 닫는 동작은 선택값·진행 중 OCR·편집 결과를 변경하지 않는다. 닫기 동작과 키보드 이동을 제공하고 닫은 뒤 정보 아이콘으로 초점을 돌려준다. 기존 CPU 사용 안내는 모델 설명과 별개로 계속 표시한다.

권장 형식과 실제 지원 형식을 구분한다. Markdown 구현 전에는 VL의 '권장: Markdown / 현재 앱: TXT, 구조화 출력 개발 예정' 상태를 안내한다. 선택한 모델·장치·실행 경로가 변경되면 해당 설명도 같은 정보를 사용한다.

## 출력 형식 선택과 Markdown 저장

- TXT를 기본값으로 유지하며 사용자가 출력 형식을 선택한다. 모델 선택만으로 형식·보정 설정을 조용히 변경하지 않는다.
- 첫 구조화 Markdown 경로는 VL 1.6 공식 문서 파이프라인으로 한정한다. 지원하지 않는 모델·경로 조합은 비활성화하거나 실행 전 조치 방법을 안내한다. 모델 자체의 잠재 기능과 앱의 실제 지원 범위를 혼동하지 않는다.
- 블록 종류·읽기 순서·위치·본문·표·수식·그림을 담는 공통 결과를 정의한다. 실제 제공되는 위치·신뢰도만 기록한다.
- 제목·목록·본문·표·수식은 인식된 구조를 Markdown에 반영한다. 단순 표는 Markdown 표로, 병합 셀 등은 보존 가능한 표 표현과 원본 이미지를 검토한다. 미지원 구조는 확인 대상으로 남긴다.
- 차트·그림은 잘라낸 로컬 이미지를 보존하고 상대 경로로 연결한다. 축·범례·수치는 실제 인식 결과와 원문을 대조하며, 차트를 임의의 설명·추정 숫자로 바꾸지 않는다.
- `.md`와 이미지 폴더를 함께 저장한다. 기존 파일·이미지 덮어쓰기 확인, 원본 PDF 보호와 취소·부분 실패 시 완료 결과 보존을 적용한다.
- 결과에서 TXT용 줄 연결이나 Kiwi를 표·수식·코드·그림 블록에 일괄 적용하지 않는다. 본문 보정을 추가할 때는 적용 블록을 명시한다.
- Markdown 원문 편집과 미리보기를 제공하고, 사용자 수정 내용이 출력·이미지 경로 변경 중에 유실되지 않도록 한다.

선택 페이지·영역·회전·확대·OCR 해상도에 대한 기존 좌표 규칙을 유지한다. 구조 분석은 선택 영역에 적용하며 잘린 구조는 임의로 완성하지 않는다. TXT로 저장하면 이미지·표 구조가 줄어들 수 있다는 안내를 출력 형식 선택 시 제공한다.

## 구현 순서와 확인 기준

1. 모델별 안내 내용을 한곳에서 관리하고 정보 아이콘에 연결한다.
2. 표·차트·수식·다단이 있는 합성 또는 배포 가능한 문서와 기대 출력 구조를 준비한다.
3. VL 1.6 공식 문서 파이프라인, 필요한 로컬 모델과 GPU 실행 환경을 확인한다. 현 설치 버전과 새 실행 환경은 실제 호환성을 확인한 뒤 도입한다.
4. 공통 구조 결과·Markdown 저장·이미지 상대 링크·형식 선택과 편집/미리보기를 연결한다.
5. 표 셀·수식·읽기 순서·누락·이미지 경로, 페이지/영역 선택, 취소·부분 실패·저장 보호와 오프라인 처리 범위를 확인한다.

텍스트 샘플로는 복잡한 문서 품질을 확정하지 않는다. 검증 결과와 환경 변경 근거는 `docs/history/`에 기록하고 확인된 범위만 완료 처리한다. 설치·실행 명령은 코드 도입 시 실제 확인한 형태로 등록한다.
